## 총평

1라운드 Blocker 6건과 Major 12건은 v2에서 거의 다 알고리즘 수준으로 정의됐다. 취향 벡터·갱신식(ADF 1-step)·D-최적 문항 선택·종료·κ·유형 판정·추출기·정규화기·TM의 순환 대응·비전 채점 편향 대책·골든 32·비용 가드·승격 규칙(Wilson 하한)이 모두 들어 있다. 대기업 ML 리뷰에 올릴 뼈대로는 충분하다.

남은 문제는 다섯 가지다. 대부분 "사람 없이 temp 데이터와 mock으로 끝까지 간다"는 이 프로젝트의 전제에서 드러난다.
1. **측정의 기준점이 비어 있다.** x_card·TM·왕복 검증은 모두 05장 정규화기(실제 사이트 60개 코퍼스의 분위 테이블)를 거친다. 그런데 이 정규화기를 temp로 만드는 규칙이 9.2 묶음 목록에 없다. few-shot 48개도 마찬가지다(AI2-01, Blocker).
2. **진단 시뮬레이션 합격 판정이 단일 시드 점추정이다.** 여유가 표본 오차보다 작아서 시드에 따라 PASS/FAIL이 바뀐다. 실패하면 같은 시드로 상수를 튜닝하게 되어 과적합되고, 튜닝을 다 써도 끝나지 않는 경우의 종료 규칙이 없다(AI2-02).
3. **골든 M1의 축 범위 기준이 엔진 정확도와 통계적으로 맞지 않는다.** RMSE 0.12를 허용해 놓고 ±0.12 안에 95%가 들어오기를 요구한다(AI2-03).
4. **`gen_copy`는 잡당 1회라 단일 실패점인데, 실패·거부 처리가 정의되지 않았다**(AI2-04).
5. **MockProvider가 04장의 2역할 파이프라인과 구조가 다르다.** 그래서 mock 녹색이 생성 품질 경로를 검증했다는 뜻이 되지 않는다(AI2-05).

### AI2-01 · Blocker · 정규화기·few-shot 등 AI 기준 자산의 초기(temp) 생성 규칙이 없어 x_card·TM·왕복 검증을 정의대로 구현할 수 없음

- **관련 절**: 05 5.5.4(N_j = 시즌 정규화기 경험적 분포함수), 5.8.1 N-01("정규화기는 시즌 기준 코퍼스(= 그 시즌 활성 세트, n ≥ 60)에서만 적합"), 5.9(왕복 검증과 실패 절차 1단계 "운영자가 … 블라인드 라벨"), 5.5.5(유효 라벨 50개 미만이면 초기 가중치) / 04 4.10.4(TM 입력 `toL1(extractL2(render))`), 4.3 2단계 J 정의("predictL1 = … 05장 toL1과 동일 계수"), 4.18(few-shot "최소 48개, MVP 출시 조건", `approved_by NOT NULL`), 4.11.2(`config/axis_hints.json`), 4.12·4.11.2(`config/copy_templates.json`) / 09 9.2.2 묶음 B1~B17, 9.2.4 B13 temp("`url`=`https://tmp-ref-NN.invalid/`, `l1`=유형 centroid ± U(−0.15, 0.15)")
- **허점**:

M3 ③ 추출기 왕복(≤ 0.15/평균 ≤ 0.10, 05 5.9는 ≤ 0.10), M4 `survey:build`의 x_card와 카드 채택(05 5.9), 그 x_card로 도는 `sim:survey`(02 2.16.1), 생성 잡의 TM·S_free(04 4.10.4).
  - 에이전트가 정규화기를 직접 만들면 그 방식이 잠금 임계값의 통과 여부를 정한다. 예를 들어 "앵커 렌더로 분위를 적합하고 b0·b1을 predictL1에 맞추는" 방식은 왕복 검증을 저절로 통과하게 만든다(순환). 그런데 5.9 실패 절차는 사람 라벨을 요구하므로 막히면 빠져나갈 길이 없다.

  - few-shot 예시(4.18)는 "MVP 출시 조건 48개, `approved_by` 필수"인데 묶음 목록에도 temp 규칙에도 없다. 에이전트가 만들어 스스로 승인하면 `approved_by` 제약의 취지에 어긋난다. 그렇다고 0개로 두면 4.7.2 `[FEWSHOT]` 블록을 어떻게 처리할지 정해져 있지 않다. `copy_templates.json`(폴백·카피 대체 문구)과 `axis_hints.json`(축 10문장)도 내용 원천이 없다.

### AI2-02 · Major · 진단 시뮬레이션 합격 판정이 단일 시드 점추정이라 여유가 표본 오차보다 작고, 튜닝과 판정이 같은 시드이며, 조정을 다 써도 실패할 때의 종료 규칙이 없음

- **관련 절**: 02 2.16.1("조건당 가상 사용자 1,000명, PRNG 시드 20261116"), 2.16.2(합격선, "미달 시 조정 순서(상수만…)"), 2.16.4(사전 시뮬레이션, 조건당 500명) / 07 7.12.1 `release.surveySim` / 09 M4 ④("미달 시 임계값을 바꾸지 말고 02장 2.16.2 조정 절차(판별 항 가중치부터)를 따른다")
- **허점**:
  - **여유가 표본 오차보다 작다.** 2.16.4는 다음 수치를 "PASS(여유 작음)"로 적었다. P-U β=8 RMSE 0.119(합격선 0.12), 적응형 이득 RMSE −5.6%(5%), P-A 앵커 정답 0.946(95%). 그런데 0.946은 95%에 **미달**이다. P-A는 "유형당 20명"이라 n = 160이고, 표준오차는 √(0.95·0.05/160) ≈ 1.7%p다.
  - 내 근사 재현(같은 수식, n = 500, 시드 4개)에서는 결과가 이렇게 흔들렸다. P-U β=8 RMSE 0.1191 / 0.1196 / 0.1220 / 0.1235(시드 4개 중 2개 FAIL, 시드 간 SD ≈ 0.002). V-RAND 대비 top-1 이득 +1.0 / +4.6 / +10.8 / +7.6%p(1개 FAIL). RMSE 이득 5.1~7.8%. 02장 프로토타입과 코드는 다르지만, 시드 하나 차이로 판정이 뒤집힌다는 결론은 같다. n = 1,000에서도 RMSE SD는 약 0.0015라서 여유 0.001보다 크다.
  - **튜닝과 판정이 같은 표본이다.** 조정 순서 ①~⑥은 시드 20261116의 결과를 보고 상수를 바꾼다. 같은 시드로 다시 판정하면 이 시드에 맞춘 상수가 선택된다(선택 편향). 출시 판정이 실제 성능보다 낙관적이 된다.
