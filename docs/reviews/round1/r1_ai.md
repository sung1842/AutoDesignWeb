## 0. 총평

방향(넓게→좁게, 프리셋을 닻으로 한 보정, LLM에는 슬롯만 채우게 하는 제한 생성, 추출기 재사용 채점)은 업계 관점에서도 맞습니다. 다만 현재 문서에는 **알고리즘이 "이동한다 / 멀어진다 / 불확실한 축 / 취향 일치도 / 벡터 거리" 같은 말로만 적혀 있고, 수식·파라미터·데이터 구조·목표 수치가 없습니다.** 그래서 Claude Code가 자율 구현할 때 다음 핵심 결정을 전부 혼자 내려야 합니다.

1. 취향 벡터가 무엇인지 (축 개수, 범위, 연속/범주, 두 축 체계의 관계)
2. 4지선다/AB 응답으로 벡터를 어떻게 갱신하는지, 학습률은 얼마인지
3. "불확실한 축"을 어떻게 재고, 다음 문항을 어떻게 고르고, 언제 끝내는지
4. 사이트 스크린샷/computed style을 축 점수로 바꾸는 함수
5. 취향 일치도의 거리 함수와 합격선
6. 품질 지표의 목표 수치

이 6개는 Blocker입니다. 이 문서는 각 항목에 바로 붙여넣을 수 있는 수식·의사코드·수치를 제시합니다. 수치는 **초기값**이며, "시뮬레이션/로그로 보정한다"는 절차까지 함께 넣었습니다.

## 1. Blocker

### AI-01 · Blocker · §1(디자인 축/성향 축), §2, §6 — 취향 벡터의 정의(스키마·스케일·축 체계)가 없음

**허점**
- 축 체계가 두 개입니다. "디자인 축"(타이포·컬러·형태·깊이감·밀도·레이아웃·이미지·모션; 범주형과 연속형이 섞임)과 "성향 축"(미니멀↔표현적 등 6개 양극 연속축). 설문 벡터가 어느 쪽인지, 두 축이 어떻게 연결되는지 없습니다.
- 값 범위(0~1? -1~1?), 차원 수, 범주형 값(flat/glass/neumorph/clay, 서체 분류, 레이아웃 유형)의 표현 방식, 불확실성 저장 여부가 없습니다.
- 예시 "미니멀 0.8, 따뜻함 0.3, 둥근 형태 0.6, 입체감 0.2"는 성향 축과 디자인 축이 섞여 있습니다.

**왜 문제인지**
설문 갱신, 문항 선택, 일치도, 프리셋 스냅, 결과 차트, DB 스키마가 모두 이 정의에 걸려 있습니다. 정의가 없으면 에이전트가 임의로 만들게 되고, 범주형 속성을 연속값으로 평균하면 문서 §8이 스스로 경고한 "글래스+브루탈 평균 = 어정쩡" 문제가 그대로 생깁니다.

**보완안 [MVP]** (기획서 §1 끝에 "취향 모델 v1" 절로 추가)

```
[취향 모델 v1 — 2층 구조]
L1 잠재 성향 축 (연속, 설문이 직접 추정하는 대상), K = 6
  a1 minimal_expressive  0=미니멀      1=표현적
  a2 cool_warm           0=차가움      1=따뜻함
  a3 sharp_soft          0=날카로움    1=부드러움
  a4 airy_dense          0=여유        1=밀도
  a5 classic_trendy      0=클래식      1=트렌디
  a6 flat_deep           0=평면        1=입체
  - 범위 [0,1]. 0.5 = 코퍼스 중앙값(백분위 정규화, AI-09 참고)
  - 사용자 상태는 점 추정이 아니라 분포: θ ~ N(μ, Σ), MVP는 Σ를 대각(σ_k²)으로 둠

L2 범주형 스타일 속성 (설문이 확률분포로 추정, 평균하지 않음)
  depth_style ∈ {flat, soft_shadow, glass, neumorph, clay, brutal}
  font_class  ∈ {sans_geometric, sans_humanist, serif, mono, display}
  layout      ∈ {grid_classic, editorial, asymmetric, bento}
  palette     ∈ {mono_accent, analogous, complementary, duotone}
  theme       ∈ {light, dark}
  → 각 속성은 카테고리 확률벡터(합=1)로 저장

L0 디자인 토큰 (최종 출력, 사용자에게 직접 노출하지 않음)
  token = clip( preset[m].token + Σ_k A[token][k]·(μ_k − c_m,k), preset[m].range[token] )
  - m = 선택된 아키타입 프리셋(AI-07), c_m = 그 프리셋의 L1 중심
  - A = 축→토큰 민감도 표 (예시 아래)
```

### AI-02 · Blocker · §1(1~3단계) — 4지선다/AB/슬라이더 응답의 벡터 갱신 알고리즘이 없음

**허점**
"고른 쪽으로 이동, 고르지 않은 쪽에서 멀어진다"뿐입니다. 갱신 수식, 학습률, 노이즈(사용자가 대충 고르는 경우) 처리, "모두 별로/모르겠음" 처리, 단계별(4지선다/AB/슬라이더) 증거 강도 차이가 없습니다.

**왜 문제인지**
- 고정 학습률의 "벡터 끌어당기기"(예: θ ← θ + η(x_c − θ))는 문항 순서에 따라 결과가 크게 바뀌고, 마지막 몇 문항에 과적합되며, 불확실성을 만들지 못합니다. 그러면 2단계의 "불확실한 축만"(AI-03)을 구현할 수 없습니다.
- 선형 효용(w·x)으로 모델링하면 "중간이 좋은" 사용자를 표현할 수 없고 항상 극단 쪽으로 밀립니다. 디자인 취향은 **이상점(ideal point)** 모델이 맞습니다.

**보완안 [MVP]** — 이상점 다항 로짓(Plackett-Luce 1순위 = MNL) + 가우시안 사후분포(Laplace/ADF 1-step) 갱신

```
모델
  사용자 이상점 θ ∈ [0,1]^K, 사후 θ ~ N(μ, Σ)
  카드 i의 L1 벡터 x_i (AI-04/AI-10에서 측정)
  효용  u_i(θ) = − Σ_k λ_k (x_ik − θ_k)²          # 이상점 모델
       = Σ_k 2λ_k x_ik θ_k − Σ_k λ_k x_ik² + const(θ)
       = z_i·θ + b_i,   z_ik = 2λ_k x_ik,  b_i = −Σ_k λ_k x_ik²
  → θ에 대해 선형이 되므로 표준 로지스틱/MNL 베이지안 갱신을 그대로 쓸 수 있음
  선택 확률  P(c | θ) = exp(β u_c) / Σ_{j∈S} exp(β u_j)

파라미터 초기값
  λ_k = 1 (축 중요도, MVP 고정. [이후] 로그로 MLE 추정)
  β  = 8  (응답 합리성/온도. [이후] 실제 로그로 MLE 보정, 허용 범위 4~16)
  사전분포 μ0 = 0.5 (또는 용도별 사전분포, AI-08), σ0 = 0.25 (±2σ가 [0,1]을 덮음)

갱신 (한 응답마다, 클라이언트에서 수 ms)
  p_j  = softmax_j( β (z_j·μ + b_j) ),  j ∈ S (보여준 카드 집합)
  z̄    = Σ_j p_j z_j
  g    = β (z_c − z̄)                                  # 로그우도 기울기
  H    = β² ( Σ_j p_j z_j z_jᵀ − z̄ z̄ᵀ )               # Fisher 정보
  Σ'   = (Σ⁻¹ + H)⁻¹        # MVP 대각: σ_k'² = 1 / (1/σ_k² + H_kk)
  μ'   = clip( μ + Σ' g , 0, 1 )
  → "학습률"은 Σ' 자체. 정보가 쌓일수록 자동으로 작아짐(초반 크게, 후반 작게).
  → "고른 쪽으로 이동 + 안 고른 쪽에서 멀어짐"은 g = β(z_c − z̄)에 이미 들어 있음.

응답 유형별 처리
  4지선다(1단계)   : 위 식, |S| = 4
  A/B(2단계)       : 위 식, |S| = 2 (= Bradley-Terry 특수형)
  "비슷함/모르겠음": θ 갱신 없음, 문항 예산만 소모, skip_count += 1
  "모두 별로"      : θ 갱신 없음. 단, 다음 문항은 S의 반대편(μ 기준 대칭) 영역에서 추출
  슬라이더(3단계)  : 직접 관측 y_k = θ_k + ε, σ_obs = 0.10
                     K = σ_k² / (σ_k² + σ_obs²);  μ_k ← μ_k + K(y_k − μ_k);  σ_k² ← (1−K)σ_k²
  범주형 L2 속성    : 카드 i가 카테고리 c_i를 가질 때, 선택 시 Dirichlet 카운트 α[c_c] += 1,
                     안 고른 카드의 카테고리는 α[c_j] += 0 (감점하지 않음, 4장 중 1장 선택은
                     "나머지를 싫어함"의 약한 증거라 음수 갱신은 노이즈만 키움)
                     분포 = α / Σα, 초기 α = 1(균등)
  아키타입 사후    : π_m ∝ π_m · P(c | θ = c_m)  (같은 우도를 아키타입 중심으로 평가)
```

TypeScript 시그니처(에이전트용):

```ts
type AxisPosterior = { mu: number[]; var: number[] };          // 길이 K
type Card = { id: string; x: number[]; cats: Record<string,string>; archetype: string };
function updateMNL(p: AxisPosterior, shown: Card[], chosenId: string,
                   opt?: { beta?: number; lambda?: number[] }): AxisPosterior;
function updateSlider(p: AxisPosterior, k: number, y: number, sigmaObs?: number): AxisPosterior;
```

**[이후]** 대각 근사를 완전 공분산으로 확장(축 간 상관 반영), β·λ를 사용자 로그로 계층적 추정(사용자별 β = 일관성 지표로도 사용, AI-17).

**수용 기준**
- 단위 테스트: (1) 선택된 카드 방향으로 μ가 움직이고 모든 응답 후 σ_k가 단조 감소, (2) 같은 응답 집합을 순서를 바꿔 넣었을 때 최종 μ 차이 ≤ 0.05 (고정 학습률 방식은 이 테스트를 통과 못 함), (3) "모르겠음"은 μ, σ를 바꾸지 않음.
- 시뮬레이션 수용 기준은 AI-03에 통합.

### AI-03 · Blocker · §1(1·2단계), §8(보조 강도) — 불확실성 추정, 적응형 문항 선택 기준, 수렴(종료) 판단이 없음

**허점**
- "불확실한 축만 하나씩", "확실해진 축은 건너뜀"의 판단 기준(무엇이 불확실한가, 임계값)이 없습니다.
- 1단계 "매번 서로 다른 스타일이 섞여 나오게"의 선택 규칙이 없습니다(무작위? 정보량 최대화?).
- 8~10 + 10~15 = 최대 25문항인데 문항 수 근거와 조기 종료 조건이 없습니다. 4지선다 1문항의 정보량은 최대 log₂4 = 2bit이고, 6축 + 범주형 속성을 추정하려면 문항 선택이 효율적이어야 합니다.
- 설문 풀이 축 범위를 고르게 덮는지에 대한 조건이 없습니다(예: 클래식 쪽 카드가 거의 없으면 클래식 성향 사용자를 식별할 수 없음).

**왜 문제인지**
무작위 4장을 보여주면 같은 25문항으로도 추정 오차가 크게 남고 사용자 피로와 이탈이 늘어납니다. 종료 기준이 없으면 에이전트가 문항 수를 하드코딩하게 됩니다.

**보완안 [MVP]**

```
불확실성: 축 k의 사후 표준편차 σ_k (AI-02의 Σ 대각)
  확정(confirmed): σ_k ≤ 0.08     # [0,1] 척도. 95% 구간 폭 ≈ ±0.16
  불확실(open)   : σ_k > 0.08

1단계 문항 선택 (4장)
  후보: 설문 풀에서 제약을 만족하는 4장 조합을 R = 300개 무작위 샘플링
  제약: (a) 서로 다른 아키타입 ≥ 3개, (b) 카드 간 L1 거리 최소 ≥ 0.35,
        (c) 직전 3문항에 나온 카드 제외, (d) 위치(좌상~우하) 무작위 셔플
  점수: D-최적 정보량  score(S) = log det( Σ⁻¹ + H(S; μ) )     # H는 AI-02의 Fisher 정보
        MVP 대각 근사: score(S) = Σ_k log(1/σ_k² + H_kk(S))
  선택: argmax score(S). 단, ε = 0.1 확률로 제약만 만족하는 무작위 S (탐색, AI-15 로그용)

2단계 문항 선택 (A/B)
  k* = argmax_{k: σ_k > 0.08} λ_k σ_k²
  A = 현재 프로필로 컴파일한 시안에서 축 k*만 μ_k* − δ 로,  B = μ_k* + δ 로
  δ = clip(σ_k*, 0.10, 0.30)    # 사후의 좌/우 반을 가르는 질문
  나머지 축은 μ로 고정 → 1축만 다른 쌍(통제된 비교)

종료 규칙
  1단계: 최소 8문항. 8~10문항 사이에 max_m π_m ≥ 0.70 이면 종료, 10문항이면 무조건 종료
  2단계: 모든 축 확정이거나, 2단계 15문항, 또는 총 25문항이면 종료
  조기 이탈 대비: 언제 중단해도 현재 μ, π로 결과를 만들 수 있게 함(결과 화면에 "신뢰도 낮음" 표시)

설문 풀 커버리지 조건 (시즌 릴리스마다 검사)
  각 축 k에 대해 풀 카드의 x_k 분포가 [0,0.33), [0.33,0.67), [0.67,1] 구간에 각각 ≥ 15%
```

**보완안 [MVP]**

```
입력: 렌더된 후보 d의 추출 벡터 v(d) (AI-04 추출기, 생성물에도 동일 적용)
      사용자 사후 (μ, σ), 범주형 분포 q_attr, 시안 변형 종류 variant

목표 벡터 t (변형별, AI-11과 공통 정의)
  as_is    : t = μ
  bold     : t = clip(0.5 + 1.4 (μ − 0.5), 0, 1)               # 경향 증폭
  safe     : t = 0.6 μ + 0.4 c_use                              # c_use = 용도별 기준점(§8 표)

축 일치 (불확실성 가중 정규화 RMSE)
  w_k   = λ_k / (σ_k² + τ²),  τ = 0.05 (추출기 측정 노이즈 하한),  w 정규화 Σw_k = 1
  d_ax  = sqrt( Σ_k w_k (v_k − t_k)² )
  S_ax  = 100 · clip(1 − d_ax / 0.35, 0, 1)        # 가중 편차 0.35 이상이면 0점

범주 일치
  S_cat = 100 · mean_attr q_attr[ category_attr(d) ]  /  max_c q_attr[c]   # 사용자가 가장 선호하는 카테고리면 100

종합
  match = 0.7 · S_ax + 0.3 · S_cat
  보고 시 '변별 축'(a1, a4, layout, decoration) 일치를 별도 필드 S_free로 함께 기록 (순환성 감시)
```

합격선(초기값):
- 노출 후보(top-3/4)는 `match ≥ 75`, `S_free ≥ 65`. 미달 후보는 수정 루프 1회 후에도 미달이면 숨김.
- 변형 간 분리: `bold`와 `safe`의 v 간 L1 거리 평균 ≥ 0.15 (변형이 사실상 같은 시안이면 실패).

**수용 기준**
- 지표 타당성 검증 [MVP, 1인 가능]: 프로필 10개 × 시안 쌍 3개 = 30쌍에 대해 본인이 "이 프로필에 더 가까운 쪽"을 블라인드로 고르고, match 점수의 판단과 일치율 ≥ 75%.
- 골든 세트 `as_is` 시안의 90% 이상이 match ≥ 80.
- 사용자 로그(이후): 노출된 3개 중 match가 가장 높은 시안이 실제 선택될 확률 ≥ 40% (무작위 33%).

```
  0.35 ≤ max π < 0.6 이고 2위와 차이 < 0.15 → "A형 성향의 B형" 혼합 표시. 닻은 1위 유형만 사용(평균 금지)
  max π < 0.35          → "탐색형" 표시 + 결과 신뢰도 낮음 + 3단계(요소 선택) 권유
유형 이름은 고정 테이블. LLM은 설명 문구 개인화만(이름 변경 금지).
개인차 반영: μ를 c_m ± radius_m 안으로 클리핑 후 토큰 컴파일(AI-01 L0 식)
```
**수용 기준** 아키타입 중심 간 최소 L1 거리 ≥ 0.25. 시뮬레이션에서 각 유형이 배정 비율 3% 이상(사장 유형 없음). 결과 화면은 같은 프로필 입력 시 항상 같은 유형명.

### AI-14 · Major · §6, §7 — 비용·지연 예산과 상한이 없음

**허점** 후보 6개 생성 + 6회 렌더 + 비전 채점 + 수정 루프(최대 횟수 미정)까지 하면 세션당 LLM 호출이 15~25회가 됩니다. 비용 상한, 지연 목표, 초과 시 처리, 사용자 대기 UX가 없습니다. 개인 프로젝트에서는 비용 폭주가 곧 서비스 중단입니다.

```
  생성: 입력 ≈ 6k(명세+카탈로그+few-shot) × 6, 출력 ≈ 2k(레이아웃 트리) + 1.5k(카피) × 6

  → 대략 입력 60~80k, 출력 25~35k tokens
세션 비용 = Σ(입력×단가_in + 출력×단가_out)  # 단가는 모델 레지스트리 설정값에서 계산

  세션당 생성 비용 상한 $0.50, 일일 총액 상한 $10 (초과 시 신규 생성 대기열/차단)

지연 목표

```

### AI-15 · Major · §4(사용자 로그=트렌드 신호), §6(피드백·few-shot), §4(풀 70/30) — 피드백 루프 편향과 다양성 붕괴 대책이 없음

**허점**
- **노출 편향:** 사용자는 시스템이 보여준 카드 중에서만 고릅니다. 트렌드 풀 70%를 많이 보여주면 트렌드 카드가 더 많이 선택되고, 그것이 다시 "트렌드 신호"가 되는 자기강화 루프가 생깁니다.
- **위치 편향:** 4장 그리드에서 좌상단 선택이 많아집니다.
- **인기 편향/다양성 붕괴:** "좋은 시안을 유형별 few-shot으로 저장" → 선택된 시안과 비슷한 시안만 더 생성 → 출력 다양성이 줄어듭니다. 프리셋 스냅도 결과를 소수 유형으로 모읍니다.

**보완안**
```
[MVP]
- 노출 로그: impressions { session_id, step, card_ids[], positions[], policy("dopt"|"explore"),
  propensity (해당 카드 조합이 선택될 확률 추정; explore는 균등), ts }
- 카드 위치 무작위 셔플(AI-03). 주간 위치별 선택률 점검: 최대/최소 비율 ≤ 1.3
- 사용자 로그는 트렌드 신호에서 제외(MVP). 별도 '사용자 선호 지표'로만 리포트
- few-shot 라이브러리: 아키타입당 최대 5개, 90일 만료, 같은 레이아웃 패턴 중복 금지,
  프롬프트에는 무작위 1~2개 샘플링(고정 예시 금지)
[이후]
- 사용자 선택을 트렌드에 쓸 때 IPS 가중: share_f = Σ_i 1[chosen_i has f]/p_i ÷ Σ_i 1/p_i,
  p_i는 clip(propensity, 0.05) 하한
- 다양성 모니터링(주간): 노출 시안 간 평균 쌍 거리, 결과 아키타입 분포 엔트로피.
  기준선 대비 20% 이상 하락 또는 단일 아키타입 > 40%이면 경보 → 탐색 비율 ε 0.1→0.2
```
**수용 기준** impressions 테이블 존재, 위치 셔플 테스트 통과, MVP 코드에서 사용자 선택 로그가 트렌드 점수 계산에 쓰이지 않음(코드/테스트로 확인).

### AI-16 · Major · §5 — 트렌드 지표의 통계적 타당성(샘플 수, 2σ 기준, 다중비교, 소스 편향)이 없음

**허점**
- **샘플 수:** Awwwards SOTD는 주 7개 수준입니다. 주 단위 특징 비중의 2σ 급등은 대부분 노이즈입니다(n=7에서 비율 0.3의 표준오차 ≈ 0.17).
- **다중비교:** 특징 50개를 매주 2σ(양측 p≈0.046)로 검사하면 아무 변화가 없어도 주당 약 2.3개가 "급등"으로 잡힙니다.
- **2σ의 기준 분포**(무엇의 표준편차인지), 모멘텀 "직전 3기간 대비"의 기간 단위, 확산 지연의 계산법, 생애 단계(태동/상승/정점/하락)의 판정 규칙이 없습니다.
- **소스 편향:** T1 수상작은 심사위원 취향(에이전시·실험적 사이트) 편향, Dribbble은 실제 사이트가 아닌 샷, 템플릿 마켓은 판매 순위 편향, 수집 성공 여부(차단)에 따른 생존 편향이 있습니다. Google Trends·데이터랩은 디자인 특징이 아니라 검색어라서 같은 지표로 합칠 수 없습니다.

**보완안**
```
[MVP] 트렌드는 '월간 수동 큐레이션 + 단순 점유율 리포트'로 축소. 자동 급등 감지·임베딩 군집은 [이후]로 명시
  점유율: 티어 t, 특징 f, 기간 w(4주 롤링)에 대해 p̂ = (k+1)/(n+2)  (라플라스 평활)
  리포트에는 n과 95% Wilson 구간을 반드시 함께 표시. n < 20이면 "표본 부족" 표기

[이후] 자동 감지 규칙
  모멘텀: log OR = logit(p̂_최근8주) − logit(p̂_이전24주)
  신호 조건: (1) 두 창 모두 n ≥ 30, (2) 베타-이항 사후에서 P(OR > 1.5) ≥ 0.95,
            (3) 특징 전체에 대해 Benjamini-Hochberg FDR q = 0.10 적용
  확산 지연: 특징 f의 티어별 점유율 곡선 간 교차상관이 최대가 되는 지연(주), T1→T2, T2→T3
  생애 단계(T1 기준): 태동 = T1 점유율 < 5% & 신호 / 상승 = 신호 & T2 점유율 증가 /
                      정점 = 8주 기울기 |β| < 임계 & 점유율 최대 / 하락 = 기울기 유의 음수
                      ("선도층 이탈" = T1 하락 & T2·T3 여전히 상승)
  소스 보정: 티어 내 소스별 가중 = 1/소스 수 (한 소스가 티어를 지배하지 않게),
             소스별 수집 성공률을 기록하고 50% 미만 기간은 지표에서 제외
  Google Trends·데이터랩은 디자인 특징 점유율과 합산 금지 — 별도 '관심도 보조 지표'
  임베딩 군집(새 스타일 발견): 스크린샷 이미지 임베딩(예: SigLIP/CLIP 계열) +
    AI-04 특징 벡터 결합 → UMAP(10차원) → HDBSCAN(min_cluster_size = 8).
    "신규 군집" = 구성원의 70% 이상이 최근 8주 수집 & 기존 아키타입 중심과의 거리 > 0.3
    → 사람 검토 큐로만 전달(자동 아키타입 추가 금지)
```
**수용 기준** MVP 범위에 "자동 트렌드 감지 제외"가 명시됨. 리포트의 모든 점유율에 n과 신뢰구간이 붙음. [이후] 단계에서는 과거 12개월 데이터 백테스트로 사람이 인정한 트렌드 대비 정밀도 ≥ 0.5, 주당 오탐 신호 ≤ 1.

### AI-17 · Major · §8(보조 강도) — "선택 일관성 측정"의 정의와 임계값이 없음

**허점** "일관되면 자유도↑, 엇갈리면 양자택일 추가 질문·프리셋 비중↑"인데 일관성을 무엇으로 재는지, 어떤 값에서 보조 강도를 바꾸는지 없습니다.

**보완안 [MVP]**
```
일관성 C = 응답별 사후예측 확률의 기하평균을 우연 수준으로 정규화
  ℓ_t = P(c_t | μ_{t−1})  (응답 직전 사후로 계산한 실제 선택 확률)
  C = ( exp(mean_t log ℓ_t) − 1/|S| ) / ( 1 − 1/|S| ),  범위 대략 [0,1], 0 = 우연 수준
  보조: 1단계 중 동일 카드 조합 1회 재출제(위치 바꿈), 일치하면 C에 +0.05, 불일치면 −0.05
보조 강도
  C ≥ 0.5      → 자유도 '높음': 개인차 반경 = 아키타입 radius × 1.0
  0.25 ≤ C < 0.5 → '보통': × 0.7, 2단계 문항 +3
  C < 0.25     → '낮음': × 0.4, 3단계 대신 양자택일 5문항 추가, 결과에 "취향이 다양함" 안내
```
**수용 기준** 시뮬레이션에서 β_true = 16 사용자 평균 C ≥ 0.5, β_true = 2(거의 무작위) 평균 C ≤ 0.25.

### AI-18 · Major · §7 — 모델 교체 판단 규칙이 없고, 카나리 5~10%는 1인 서비스 트래픽에서 통계적으로 의미가 없음

**허점** "골든 세트 점수 + 블라인드 A/B, 실제 선택률·수정 횟수, 비용·속도·오류율"을 기준으로 든다고만 하고 결합 규칙(무엇이 얼마나 나빠지면 거절)이 없습니다. 하루 수십 세션 규모에서 5~10% 카나리로는 선택률 차이를 검출할 수 없습니다.

**보완안**
```
[MVP] 오프라인 승격 규칙 (모두 만족 시 승격)
  골든 G ≥ 기존 − 1점 (비열등), 하드 실패 0건
  블라인드 쌍비교(본인 또는 지인, 30쌍, 위치 무작위): 신규 승률 95% 구간 하한 ≥ 0.40
  비용 ≤ 기존 × 1.3, p95 지연 ≤ 기존 × 1.2, 스키마 오류율 ≤ 2%
  역할별(생성/카피/judge/태깅) 독립 평가. judge 교체 시 AI-12 보정셋 재통과 필수
[이후] 트래픽이 주 500세션 이상일 때만 온라인 카나리. 1차 지표 = 시안 채택률,
  최소 표본 = 기준 50% 대비 10%p 차이 검출(α=0.05, 검정력 0.8) ≈ 그룹당 약 390세션
```
**수용 기준** 레지스트리 설정에 위 임계값이 있고, `eval:compare --baseline X --candidate Y`가 승격/거절과 사유를 출력한다.

## 3. Minor

### AI-19 · Minor · §6 피드백 — 생성 후 수정/선택을 취향 벡터에 반영하는 강도
요소 수정은 사용자가 직접 표현한 증거이지만 용도 맥락이 섞여 있습니다. 슬라이더와 같은 칼만 갱신을 쓰되 σ_obs = 0.15(설문보다 약하게), 시안 선택은 MNL 갱신에 β × 0.5. 이렇게 갱신된 프로필은 "용도별 조정 프로필"로 따로 저장하고, 원래 설문 프로필은 덮어쓰지 않음(재검사 신뢰도 보호). [MVP]

### AI-20 · Minor · §1 4단계 — "가장 닮은 실제 사이트 3곳" 검색 규칙
AI-05의 가중 거리 d_ax(t = μ)로 최근접 탐색 + 범주 일치 보너스, 같은 도메인 중복 금지, 3곳 중 최소 1곳은 다른 아키타입(다양성). 링크 허용 목록(robots·약관 확인된 도메인)에 있는 사이트만. [MVP]

### AI-21 · Minor · §4 — 가중치 감쇠(반감기 6개월)와 풀 비율 70/30의 정의
감쇠 가중 w(age) = 0.5^(age_days/182). "클래식 풀" 정의 필요: 수집 후 18개월 이상 & 시즌 3개 이상 연속 활성 & 사람 승인. 감쇠는 트렌드 점수에만 적용하고 클래식 풀 카드의 설문 노출 확률에는 적용하지 않음(그러지 않으면 30%가 사실상 사라짐). 70/30은 문항 선택(AI-03)의 후보 샘플링 비율로만 적용하고, 정보량 최대화가 이를 다시 왜곡하지 않도록 세션 전체 노출 비율을 60~80% 범위로 제한. [MVP]

### AI-22 · Minor · §2 — 4단계 사람 검수의 1인 운영 용량
주간 신규 레퍼런스 전량 검수는 1인이 감당하기 어렵습니다. 검수 큐 = unstable 플래그 + 무작위 10% + 신규 군집 대표 샘플, 주 30분 상한. 미검수 카드는 설문 탐색 슬롯에만 사용. [MVP]

### AI-23 · Minor · §4, §6 — 응답·선택 로그의 학습 이용 동의
선택 로그를 트렌드·few-shot·모델 평가에 쓰려면 수집 시 고지·동의 항목과 보존 기간(예: 원 응답 2년, 익명화 후 집계 무기한)이 필요합니다. 법무 리뷰어 영역과 겹치므로 데이터 필드 목록만 공유. [MVP]

### AI-24 · Minor · §1 — 문항 피로도
25문항 상한은 모바일에서 길 수 있습니다. 1단계 카드 썸네일은 모바일에서 2×2가 아닌 세로 스와이프 2장씩 비교(4지선다를 2단 토너먼트로) 옵션을 [이후] A/B로 검토. AI-03 시뮬레이션으로 "문항 수 대비 RMSE 곡선"을 그려 최소 문항 수를 데이터로 정할 것.
