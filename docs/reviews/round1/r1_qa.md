# R1 QA 리뷰 — 디자인 취향 진단 기반 웹 시안 자동 생성 서비스 (spec_v1)

- 리뷰어 관점: QA 리드 (수용 기준, 테스트 가능성, 엣지 케이스, 비결정성 시스템 검증, 성능, 호환성, 접근성, 출시 게이트, 자율 구현 마일스톤 검증)
- 핵심 질문: **AI 에이전트가 이 기획서로 수 시간 자율 구현했을 때, "기준치만큼의 결과가 나왔다"를 기계적으로 판정할 수 있는가?**
- 한 줄 결론: **판정할 수 없다.** v1은 방향과 아이디어 문서로는 좋지만, 기능마다 입력·출력·합격선이 없다. "취향 일치도", "조화 점수", "AI 티 린터", "골든 세트"처럼 측정 장치의 이름은 있는데 **임계값, 공식, 데이터 형식이 하나도 없다.** 그래서 에이전트가 스스로 기준을 정하고 스스로 통과시키는 구조가 된다.

## 1. 상세 항목

### QA-01 · Blocker · 기능별 수용 기준(AC)이 전혀 없음
- **관련 섹션**: 1장 전체(1~5단계), 3장, 6장, 8장
- **허점**: 어느 기능에도 "이게 되면 완료"라는 문장이 없다. 예를 들어 1단계는 "4장 중 고르면 벡터가 이동한다"까지만 쓰여 있다. 얼마나 이동하는지, 어떤 상태가 되면 1단계가 끝나는지가 없다.
- **왜 문제인가**: 자율 구현 에이전트는 AC가 없으면 "화면이 뜨고 에러가 없음"을 완료로 본다. 리뷰 게이트(C2)는 모든 기능에 AC를 요구한다.
- **보완안** (기획서에 '부록 A. 수용 기준'을 새로 만들어 붙여넣기. 형식은 Given/When/Then, ID는 `AC-<단계>-<번호>`):

```
AC-1-01 Given 새 세션, When 1단계 시작, Then 4장의 카드가 표시되고 4장의 스타일 벡터 쌍별 L2 거리 최소값 ≥ 0.35(6축, 0~1 정규화)이다.
AC-1-02 Given 카드 1장 선택, When 다음 문항으로 이동, Then 취향 벡터가 §3.2 공식대로 갱신되고(소수 4자리 일치), 응답 로그에 {questionId, shownCardIds, chosenCardId|null, ts}가 저장된다.
AC-1-03 1단계는 8문항 완료 시, 또는 모든 축 확신도 ≥0.7이면 최소 8문항 이후 종료된다. 최대 10문항.
AC-1-04 같은 세션에서 같은 카드는 두 번 노출되지 않는다.
AC-2-01 2단계 각 문항은 확신도 <0.7인 축 중 확신도가 가장 낮은 축 1개만 다른 A/B 쌍이다(나머지 축 차이 ≤0.05).
AC-2-02 모든 축 확신도 ≥0.7 또는 15문항 도달 시 2단계 종료. 확정된 축은 다시 묻지 않는다.
AC-3-01 (MVP 제외 시 생략) 요소 선택·슬라이더 조작은 token 값만 바꾸고, 레이아웃 트리 JSON의 해시는 그대로다.
AC-4-01 결과 화면에 유형명 1개, 설명 2~4문장, 6축 점수(0~100 정수) 차트, 유사 레퍼런스 3개(링크 포함)가 표시된다.
AC-4-02 같은 응답 로그를 다시 재생하면 같은 유형·같은 점수·같은 유사 사이트가 나온다(결정론).
AC-5-01 브랜드 입력 제출 후 p95 90초 안에 시안 3개가 노출된다(QA-14). 3개 모두 QA-04의 Hard 게이트를 통과한다.
AC-5-02 3개 시안은 각각 '취향 그대로/용도 최적/균형' 라벨을 갖고(QA-17), 시안 간 추출 벡터 L2 거리 ≥0.15이다(서로 충분히 다름).
AC-5-03 시안 1개를 고르면 '완성' 화면에서 HTML zip과 React 코드를 내려받을 수 있고, QA-19 기준을 통과한다.
```

- **수용 기준**: 1장의 모든 단계와 6·8장의 모든 파이프라인 단계에 AC가 1개 이상 있고, 각 AC에 대응하는 자동 테스트 ID가 추적표(AC ↔ 테스트 파일)에 있다.

### QA-03 · Blocker · 취향 벡터 모델·업데이트 공식·종료 조건이 없음
- **관련 섹션**: 1장 1~2단계, 1장 '성향 축', 8장
- **허점**: 축 개수(디자인 축 8개와 성향 축 6개가 섞여 있음), 값 범위, 이동량, "멀어진다"의 크기, 확신도 정의, 디자인 축과 성향 축 사이 매핑이 모두 없다.
- **왜 문제인가**: 설문 엔진은 서비스의 핵심 로직이다. 공식이 없으면 단위 테스트의 기대값을 쓸 수 없다. 에이전트마다 다른 수식이 나오고 회귀 테스트도 불가능하다.
- **보완안** (기획서 '§3.2 취향 벡터'로 붙여넣기. 수치는 MVP 초기값이며 골든 세트로 튜닝한다):

```
- 취향 벡터 v ∈ [0,1]^6, 축 순서 고정:
  [minimal_expressive, cold_warm, sharp_soft, airy_dense, classic_trendy, flat_deep]
  (0 = 왼쪽 극, 1 = 오른쪽 극). 초기값 v0 = [0.5]*6.
- 디자인 축(타이포·컬러·형태…)은 '프리셋 → 디자인 token' 매핑으로만 다룬다. 사용자 벡터는 6축만 가진다.
- 카드 선택 시 갱신(1단계):
  v ← clip( v + η·(s_chosen − v) − μ·mean_{u∈unchosen}(s_u − v), 0, 1 ),  η = 0.30, μ = 0.05
- A/B 선택 시 갱신(2단계): 대상 축 k만 v_k ← v_k + η2·(s_chosen,k − v_k), η2 = 0.40
- '모르겠음/둘 다 별로' 응답: v는 바꾸지 않고, 해당 문항의 축들에 skip 카운트 +1
- 축 확신도 c_k = clip(1 − std(선택된 카드들의 축 k 값)/0.35, 0, 1) × min(1, n_k/3)
  (n_k = 축 k에 정보가 있는 응답 수. 응답이 3개 미만이면 확신도에 페널티)
- 벡터는 항상 '응답 로그 재생'으로 계산한다(상태를 누적 저장하지 않음 → 결정론, 뒤로가기 지원).
```

- **테스트 케이스** (단위 테스트, 고정 기대값):
  - TC-V-01: v0에서 s_chosen=[1,1,1,1,1,1], unchosen 3개가 모두 [0.5]*6이면 → v=[0.65]*6
  - TC-V-02: 같은 카드 방향을 10회 연속 선택해도 v는 [0,1] 범위 안에 있고, 단조 수렴한다
  - TC-V-03: 응답 로그 순서를 바꾸면 결과가 달라질 수 있다(경로 의존을 문서에 명시). 같은 로그를 재생하면 항상 같은 값
- **수용 기준**: `lib/taste/vector.ts`가 순수 함수이고 TC-V-01~03을 포함한 테스트 ≥15개가 통과한다. 분기 커버리지 ≥90%.

### QA-04 · Blocker · 품질 게이트(취향 일치도·조화 점수·AI 티 린터) 공식과 임계값이 없음
- **관련 섹션**: 3장 2, 6장 4, 8장 조화 규칙
- **허점**: "채점", "린터", "조화 점수 미달 시 숨김"이라는 말만 있고, 무엇을 어떻게 재서 몇 점이면 통과인지 없다. 비전 채점(LLM)이 사실상 판정자가 될 위험이 있다.

**(1) Hard 게이트 — 하나라도 실패하면 시안 폐기 또는 수정 루프로 보냄**
| ID | 규칙 | 측정 방법 (Playwright 렌더 후) |
|---|---|---|
| H-01 | 레이아웃 트리 JSON이 스키마 검증 통과 | zod/ajv |

## 3. 루브릭 판정

### C2 AI 구현 가능성 — **FAIL**
에이전트가 스스로 내려야 하는 제품 결정이 많다. 취향 벡터 공식(QA-03), 품질 임계값(QA-04), MVP 범위(QA-05), 픽스처 데이터 자체(QA-07), 시안 개수·라벨 모순(QA-17), 실패 시 동작(QA-11), 입력 스키마(QA-09)가 그 예다. 무엇보다 **"기준치만큼의 결과"를 판정할 합격선이 없어서, 자율 구현 결과를 기계적으로 PASS/FAIL로 판정할 수 없다.** 테스트·임계값을 수정하지 못하게 막는 장치(QA-06)도 없어 에이전트가 스스로 통과시킬 위험이 있다.

### C3 대기업 통과 — **FAIL**
QA 게이트 기준으로 보면, 네이버·카카오·토스 수준의 리뷰에서 요구하는 테스트 전략서(계층별 전략, 비결정성 대응), 출시 기준(품질 게이트), 성능 SLO, 지원 환경 매트릭스, 접근성 기준, 장애 대응(폴백) 정의가 없다. 생성물 렌더링 보안(QA-20)도 정의되지 않아 보안 리뷰 탈락 사유가 된다.

### PASS로 가기 위한 최소 조건
QA-01~07을 반영하고(부록 A 수용 기준, §3.2 벡터 공식, §6.4 품질 게이트, §0 범위, §10 출시 게이트, §11 마일스톤, 픽스처 입력 패키지), QA-08~22의 표와 테스트 케이스를 붙여넣고, QA-17의 모순을 정리해야 한다.
