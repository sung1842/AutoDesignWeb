- 대상: `docs/spec/v2/01_ux_screens.md`(1.3·1.4·1.5.2·1.6~1.12·1.14~1.20 정독). 다른 장은 UX 관련 절만 grep으로 확인했다(00 §5.4·§7.1·§8.2·§8.3, 02 2.6.1·2.9·2.12.2·2.13, 04 4.7.1 `gen_copy` 실패 규칙·4.9.4 사진 톤, 06 6.4.3 `POST /api/surveys`·`ResultView`·`GenerationView`·`MockupCard`, 07 7.2·7.6.2·TC-R-16).
- 기준: `rubric.md`, `decisions_v3.md`(S-01~S-41, UX 관련 S-12·S-14·S-16·S-18·S-27·S-29~S-32·S-34·S-37), 2라운드 `r2_ux.md`(UX2-01~09)
- 규칙: 2라운드 항목은 결정 문서가 아니라 **장 본문 grep 결과**로 상태를 판정했다. 해결된 항목은 다시 쓰지 않는다. 새 항목은 2라운드 반영 편집이 만든 불일치와 반영 누락을 중심으로 적었다.

## 총평

2라운드 Major 3건(UX2-01~03)의 **핵심 결정**은 01장에 들어갔다. S03 ② 안내는 우선순위·키·백분율 0건으로 정리됐고, mobile 1단계는 고정 높이 창, desktop은 `w_min = 480px`, 편집 허용은 기기 기준으로 바뀌었다. 01장 구조(IA, 상태 매트릭스, 오류 표, 카피 표, 접근성, 계측, 사용성 테스트)는 여전히 대기업 디자인 리뷰 수준이다.

다만 반영이 "결정 문장"에서 멈춘 곳이 많다. 그래서 에이전트가 직접 정해야 하는 지점이 새로 생겼다.
1. **반영 누락으로 남은 모순.** 1.9 9번은 여전히 "mobile(<768)에서는 내보내기 숨김"이라 S-31과 정면으로 충돌한다. 2라운드 수용 기준(뷰포트별 Playwright, 200% 확대 E2E, ② 안내 1개)은 하나도 01장에 들어오지 않았다.
2. **새 규칙이 일부 뷰포트에서 성립하지 않는다.** `w_min = 480`은 tablet(768~1023)과 가로 모드 휴대폰에서 폭 항 때문에 도달할 수 없다. mobile 세로 예산 232px에는 "다 별로예요"(44px)와 safe-area가 빠져 있다.
3. **화면이 쓸 데이터가 API에 없다.** S03 ②의 κ < 0.50·시즌 조정 판정, S08의 `drafts.photoSubstituted`·템플릿 덱(S-12) 안내는 `ResultView`·`MockupCard`·`GenerationView`에 해당 필드가 없다.
4. **다른 장 결정이 화면으로 내려오지 않았다.** S-18(재검사 유도·A5 인앱 시트)은 00장에만 있고, 01장 화면·상태·카피·이벤트와 06장 API에 없다.

모두 문서 수정과 작은 계약 추가로 고칠 수 있다(1인 기준 반나절~1일).

### UX3-01 · Major · 자극물 크기 규칙이 tablet·좁은 desktop·A/B·mobile 예산에서 성립하지 않음

- **관련 절**: 01 1.4.3 표, 1.4.2 R5, 1.4.11 와이어프레임, 1.14.3 "mobile 페이저 [이전 카드][다음 카드]", AC-01-08 / 07 7.6.2
- **허점**:
  - **`w_min = 480`에 도달할 수 없는 폭 구간이 있다.** 1단계 desktop 공식의 폭 항은 `(vw − 88)/2`이다. 그래서 vw < 1048이면 높이 제약을 풀어도 w < 480이다. tablet은 "같은 공식, 여백 48"이라 768px에서 `(768 − 96 − 24)/2 = 324px`, 축소율 0.25다. 2라운드에서 문제 삼은 0.28보다 더 나쁘다. 가로로 돌린 휴대폰(844×390)은 R5상 desktop 클래스(≥ 768)가 된다. 이때는 2×2에 w ≈ 378이고, mobile 규칙인 `card_h < 300` 회전 안내도 적용되지 않는다. "미달이면 세로 스크롤 2×2"가 해결하지 못하는 경우의 동작은 정의되지 않았다.
  - **2단계 A/B에는 하한이 없다.** 폭 `min((vw − 88)/2, 588)`은 768px에서 340px(0.27)이다. A/B는 Δ = 0.30 한 축 차이만 보는 문항이라(02 2.3) 축소에 가장 민감한데도 S-30은 1단계만 다뤘다. mobile A/B 토글의 카드 높이 규칙도 없다. 1단계처럼 고정 창을 쓰는지, 문서 높이 그대로인지 정해져 있지 않다.
  - **mobile 세로 예산이 맞지 않는다.** `232 = 56 + 8 + 48 + 120`에는 "하단 바 위 텍스트 버튼 '다 별로예요'(44px)"와 `env(safe-area-inset-bottom)`(iPhone 34px)이 빠져 있다. 390×664에서 계산하면 232 + 432(card_h) + 44 = 708 > 664라서, UX2-02 수용 기준(페이지 스크롤 0)이 실패한다. "하단 고정 바(120) **한 줄에** 버튼 48 + 썸네일 64×4 + '2 / 4'"는 328px 폭에 들어가지 않는다. 120px이라는 높이를 보면 두 줄이 의도로 보인다. 1.14.3이 요구하는 [이전 카드][다음 카드] 버튼은 자리가 없다. 1.4.11 mobile 와이어프레임은 S-30 이전 배치 그대로다.
  - 2라운드 수용 기준(360×640·390×664·412×780 스크롤 0, 1280×720·1366×657 폭 ≥ 480)은 01장에 없고, AC-01-08은 여전히 폭만 본다.
- **왜 문제인가**: tablet은 지원 범위(1.3.1)이고 S01~S08 완주 대상이다. 이 구간에서 측정이 왜곡되거나 레이아웃이 깨져도 테스트에 걸리지 않는다. 에이전트는 1열로 바꿀지, 토글을 쓸지, 축소를 받아들일지, 어떤 요소를 줄일지 스스로 정해야 한다(C2).
- **보완안 [MVP]**:
  1. **1단계 desktop/tablet**: 2열 폭 `w2 = min((vw − 2m − 24)/2, 588)`이 480 미만이면 **1열 세로 목록**으로 바꾼다. 폭은 `w1 = min(vw − 2m, 800)`이고, 카드 4장을 세로로 놓고 페이지 스크롤을 쓴다(m = desktop 32, tablet 48). 위치 순서는 `items` 순서 그대로다(R2). 768px이면 w1 = 672(0.525)다.
  2. **2단계 desktop/tablet**: 좌우 폭이 480 미만이면 mobile과 같은 **토글 비교**를 쓰고, 자산은 desktop 자산, 폭은 `w1`이다.
  3. **mobile 예산**: `card_h = 100dvh − 276 − env(safe-area-inset-bottom)`이다(56 + 8 + 48 + 하단 바 120 + "다 별로예요" 44). 하단 바는 **두 줄**로 한다. 1줄은 썸네일 4칸 + "2 / 4", 2줄은 [이걸로 할게요]다. 썸네일 탭이 스와이프를 대체하는 단일 포인터 경로이므로 1.14.3의 [이전 카드][다음 카드]는 "썸네일 탭으로 대체"로 고친다(2.5.1 충족). mobile A/B도 같은 고정 창(`card_h`, 하단 바 1줄 = 세그먼트 [A][B] + 응답 버튼)을 쓴다.
  4. 가로 모드 휴대폰 판정은 폭이 아니라 `(pointer: coarse) && vh < 500`으로 하고 회전 안내를 띄운다. R5 자산 클래스는 그대로 둔다.
  5. 1.4.11 mobile 와이어프레임을 새 배치로 다시 그린다.
- **수용 기준**:
  - 360×640, 390×664, 412×780(safe-area 34 에뮬레이션 포함)에서 S02 1·2단계의 응답 버튼과 "다 별로예요/차이를 모르겠어요"가 페이지 스크롤 없이 보이고, 카드 `scrollHeight == clientHeight`다.
  - 768×1024, 1024×768, 1280×720, 1366×657에서 1·2단계 카드 표시 폭이 ≥ 480px다(1열·토글 전환 포함).
  - 844×390 터치 에뮬레이션에서 회전 안내가 보이고 응답 버튼은 비활성이다.
  - 위 뷰포트를 07 7.6.2 S02 검증 뷰포트에 추가한다.

### UX3-02 · Major · S-31 반영 누락: 좁은 뷰포트 내보내기 숨김이 남아 있고 확대 검증 기준이 없음

- **관련 절**: 01 1.9 9번, 1.8.7, 1.3.1, 1.14.2 "확대·리플로" 행, 1.12.1 S09, 1.7.1, 1.2 S11, 1.20 S-31 행 / 07 7.6.2 "S09 편집은 1024px 이상 권장"
- **허점**:
  - 1.9 9번 "mobile(<768)에서는 내보내기 메뉴를 숨긴다(1.8.7)"가 그대로 남아 있다. 1.8.7은 "편집 허용 + 뷰포트 < 768 … 내보내기도 가능하다"라고 해서 둘이 정면으로 충돌한다. 1.20은 1.9를 "반영"으로 적었다. 데스크톱에서 200% 확대(CSS 640px)하면 1.9대로 구현할 경우 내보내기가 사라져 UX2-03 문제가 다시 생긴다.
  - 1.14.2의 "S09 desktop 패널은 예외 없이 드로어 전환"은 768~1023 규칙이다. < 768은 1열 탭(1.8.7)인데 1.14.2 문구는 고쳐지지 않았다.
  - 판정 시점이 없다. `matchMedia`는 클라이언트 전용이라 SSR 첫 렌더에서 무엇을 그릴지 정해야 한다. Android는 회전하면 `screen.width`가 바뀌어 같은 기기에서 편집 허용 여부가 뒤집힐 수 있다.
  - 1.12.1 S09에 `mobile_readonly`는 있지만 `narrow_edit`(1열 탭) 상태가 없어 시각 회귀·axe 대상에서 빠진다.
  - UX2-07(터치 소형 기기 S08 주 행동)도 그대로라, [이 시안 다듬기]가 읽기 전용 화면으로 이어진다. 1.2는 S11 진입에 "S08(mobile)"을 적었지만 S11은 S09 모달이라 S08에서 열 수 없다.
- **왜 문제인가**: 확대 사용자의 핵심 기능 손실(WCAG 1.4.4·1.4.10, KWCAG)이라는 2라운드 C3 사유가 본문에 그대로 남아 있다. 문장끼리 충돌하니 에이전트가 하나를 골라야 한다(C2).
- **보완안 [MVP]**:
  1. 1.9 9번을 "편집 불허 기기(1.3.1 판정)에서는 내보내기 메뉴를 숨긴다. 편집 허용 기기는 뷰포트와 무관하게 내보내기가 가능하다"로 고친다. 1.14.2 행은 "< 768은 1열 탭(1.8.7), 768~1023은 드로어"로, 07 7.6.2는 "01장 1.3.1 판정"을 참조하도록 고친다.
  2. 판정 규칙을 덧붙인다. 판정은 S09 마운트 시 1회만 하고 세션 동안 고정한다(회전해도 다시 판정하지 않음). SSR은 편집 레이아웃 골격(스켈레톤)을 그리고, 하이드레이션 후 불허면 읽기 전용으로 바꾼다.
  3. 1.12.1 S09 기타에 `narrow_edit`을 추가한다.
  4. 편집 불허 기기의 S08 레일: 주 CTA는 `drafts.mobile.cta` "PC에서 다듬기"(현재 `/edit/[mockupId]` 링크 복사 + 안내 "로그인하면 PC에서 이어서 할 수 있어요")로, 보조는 [공유 링크 만들기]로 한다. 보조 CTA는 `/edit/[mockupId]?modal=share`(1.8.7 읽기 전용 화면 위의 S11)로 연다. 1.2 S11 진입을 "S09, S09 읽기 전용"으로 고친다.
- **수용 기준**:
  - 1280×800 + CSS 200% 확대(뷰포트 640, `pointer: fine`)에서 키보드만으로 스타일 탭 조작 1회 → 저장 → S10 다운로드를 완료하고, 가로 스크롤이 0이다.
  - 390×844 `hasTouch`·`pointer: coarse`에서 S09는 읽기 전용이고 내보내기 메뉴 0건, S08 주 CTA 문구가 `drafts.mobile.cta`와 일치하며 공유 모달이 열린다.
  - 01장 전체에서 "<768"과 내보내기 숨김이 함께 나오는 문장이 0건이다(문서 grep).

- **수용 기준**: AC-01-44 순회 목록에 위 상태가 모두 포함되고 각각 렌더된다.

### UX3-10 · Minor · 초대 링크 자동 적용(UX2-08) 미반영

- **관련 절**: 01 1.1.4, 1.5.1, 1.12.2 `INVITE_REQUIRED` / 00 §7.2 비공개 베타
- **허점·보완**: 2라운드 보완안이 반영되지 않았다. `/?invite=<code>` 값을 localStorage `tf_invite`에 보관했다가 로그인 직후 `POST /api/invites/redeem`을 자동 호출하고, 실패하면 조용히 지운다. `BETA_INVITE_ONLY=true`이면 S01 정보 줄에 `landing.betaNote` "시안 생성은 초대받은 분부터 열려 있어요"를 표시한다.
- **수용 기준**: 초대 링크로 들어온 E2E 사용자가 `INVITE_REQUIRED` 박스를 0회 보고 S07에 도달한다.
