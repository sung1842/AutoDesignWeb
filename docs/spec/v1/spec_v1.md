# 디자인 취향 진단 기반 웹 시안 자동 생성 서비스 — 기획 정리 (v1)

실제 사이트로 큰 취향부터 잡고 점점 좁혀가는 방식. 흐름, 가중치 설계, AI 느낌 제거 방법을 정리한다.
(제작자: 풀스택 개발자 1인 개인 프로젝트. 기획 후 마스터 프롬프트로 Claude가 수 시간 자율 구현하는 것을 목표로 함)

## 1. 전체 흐름 (넓게 → 좁게)
### 1단계. 실제 사이트로 큰 취향 잡기 (8~10문항)
- 레퍼런스 사이트 4장 중 마음에 드는 것을 고르는 방식. 매번 서로 다른 스타일이 섞여 나오게 구성.
- 각 사이트에는 미리 스타일 벡터를 붙여둔다. 예: 미니멀 0.8, 따뜻함 0.3, 둥근 형태 0.6, 입체감 0.2 …
- 고르면 고른 사이트의 벡터 쪽으로 취향 벡터가 이동, 고르지 않은 쪽에서는 멀어진다.
### 2단계. 세밀 조정 (10~15문항)
- 1단계 결과 근처에서 불확실한 축만 하나씩 바꾼 A/B 시안. 확실해진 축은 건너뜀.
### 3단계. 요소 단위 미세 조정 (선택)
- 폰트 페어링, 버튼, 카드, 컬러 팔레트 직접 선택. "조금 더 둥글게" 슬라이더.
### 4단계. MBTI식 결과
- 유형 이름과 설명(예: "고요한 에디토리얼형"). 축별 점수 차트와 가장 닮은 실제 사이트 3곳.
### 5단계. 시안 생성과 완성
- 사이트 용도와 취향 벡터를 합쳐 시안 3~4개(취향 그대로 / 과감하게 / 안정적으로). 하나 고르면 다듬어 완성.

디자인 축(초기 제안): 타이포(서체 분류, 페어링, 크기 비율, 자간), 컬러(팔레트 구조, 명도 대비, 다크), 형태(radius, 테두리), 깊이감(그림자, 블러, flat/glass/neumorph/clay), 밀도(여백), 레이아웃(그리드, 비대칭, 벤토, 에디토리얼), 이미지/장식, 모션. 스타일 양식 = 축 값 프리셋. 컴포넌트 라이브러리 하나 + CSS 변수 테마.
성향 축 예: 미니멀↔표현적, 차가움↔따뜻함, 날카로움↔부드러움, 여유↔밀도, 클래식↔트렌디, 평면↔입체.
기술 스택 초안: Next.js + Tailwind v4 + CSS 변수 token, shadcn/ui 베이스, Supabase(Postgres), Playwright(썸네일·검증), 결과물 HTML/React 코드 내보내기, Figma 내보내기는 2차.

## 2. 가중치를 어떻게 매길까
1. 객관적 추출(자동): Playwright + getComputedStyle로 폰트, radius, 그림자, 색상 분포, 여백.
2. 주관적 판단(AI 보조): 스크린샷을 비전 모델로 기준표 채점.
3. 사람 검수: 최종 값 확정. 초기 시드 50~100개, 이후 4장 파이프라인으로 계속 갱신.
### 주의: 저작권·약관
- 내부 분석용으로만 실제 사이트 사용, 설문에는 같은 스타일 벡터로 재현한 오리지널 시안. 실제 사이트는 결과 화면에서 링크로만.

## 3. AI 느낌을 지우는 방법
AI 티 패턴: 보라~파랑 그라디언트, 그라디언트 텍스트, 전부 Inter, 정중앙 히어로 + "✨ New" 배지, 3열 아이콘 기능 카드, 균일한 rounded-xl+흐린 그림자, 같은 섹션 리듬, 컬러 블롭/무의미한 글래스, 기본 Lucide/이모지 아이콘, 일반론 카피, 네온 글로우, 목적 없는 벤토.
지우는 방법:
1. 미적 판단을 LLM에 맡기지 않기 — token 값은 실제 사이트 추출값/검증 프리셋에서만, LLM은 슬롯 채우기.
2. AI 티 린터 — 금지 패턴, 기본값 검사, 반복 검사, 걸리면 재생성.
3. 타이포 — 개성 있는 페어링, 한글 헤드라인 자간 -0.02em, 본문 행간 1.6~1.7, 과감한 크기 대비.
4. 의도적 비대칭과 리듬.
5. 시그니처 디테일 하나(프리셋별 후보).
6. 절제와 질감 — 2~3색, 그레인, 실사진.
7. 진짜 같은 콘텐츠 — 브랜드 정보 입력받아 구체적 카피, 일반론 금지, 내비/푸터까지.
8. 평가 루프 — 스크린샷 비전 채점(보조) + 초기 사람 라벨링.

## 4. 레퍼런스는 고정값이 아닌 계속 갱신되는 데이터셋
수집 파이프라인: 1) 매주 소스 티어별 URL 수집(RSS·API·허용 방식, 막히면 수동) 2) 특징 추출(수치 + 임베딩 + 비전 태깅) 3) 저장(수집일, 티어, 벡터; 스크린샷 내부용) 4) 가중치 감쇠(반감기 6개월) 5) 분기 시즌 릴리스(예: 2027-S1).
설문 풀: 트렌드 풀 70%(최근 6개월), 클래식 풀 30%. 사용자 선택 로그도 트렌드 신호.

## 5. 트렌드의 정의와 판단 기준
트렌드 = 선도층에서 비중이 늘고 확산층·대중층으로 퍼지는 디자인 특징. 티어별 특징 비중 변화로 측정.
- T1 선도층(Awwwards SOTD, FWA, CSSDA, Godly, 유명 스튜디오, Figma Config) 매주
- T2 확산층(Dribbble·Behance 인기, Framer·Webflow 템플릿, Product Hunt, 디비컷·GDWEB) 매주
- T3 대중층(대형 브랜드·국내 서비스, 웹빌더 템플릿, Google Trends·네이버 데이터랩) 월 1회
지표: 점유율, 모멘텀(직전 3기간 대비), 확산 지연. 생애 단계: 태동/상승/정점/하락. 핵심 신호 = 선도층 이탈 시점.
주기: 매주 수집, 매월 리포트, 분기 시즌. 이벤트 트리거(WWDC, I/O, Config), 급등 감지(2σ), 임베딩 군집으로 새 스타일 발견. 최종 승인은 사람.

## 6. AI가 사용자 취향대로 디자인하도록 유도하는 시스템
파이프라인: 1) 디자인 명세서 컴파일(규칙 코드: token, 레이아웃 패턴, 섹션, 카피 톤, 시그니처, 금지 목록) 2) 제한된 생성(컴포넌트 부품만으로 레이아웃 트리 JSON + 카피, CSS 화이트리스트, 스키마 검증) 3) 후보 6개 4) Playwright 렌더 후 채점: 취향 일치도(같은 추출기로 벡터 거리), 린터, 품질(대비·넘침·깨짐), 비전 채점 5) 수정 루프(구체적 차이 피드백) 6) 상위 3~4개 노출.
피드백: 요소 단위 수정은 token만 변경, 선택·수정을 벡터에 반영, 좋은 시안을 유형별 few-shot으로 저장.
골든 세트: 가상 사용자 20~30개로 프롬프트/모델 변경 회귀 테스트.

## 7. 모델 선택 기준과 교체 구조
역할별 모델: 페이지 생성 / 한국어 카피 / 비전 채점 / 레퍼런스 태깅·임베딩(저렴). 기준: 골든 세트 점수 + 블라인드 A/B, 실제 선택률·수정 횟수, 비용·속도·오류율, 약관·데이터 정책. 후보 발굴은 WebDev Arena, Design Arena, 릴리스 노트.
교체 절차: 감지(매주) → CI 자동 평가 → 프롬프트 맞추기 → 카나리 5~10% → 승격/롤백.
구조: 모델 게이트웨이(Vercel AI SDK, LiteLLM, OpenRouter), 모델 레지스트리(설정), 프롬프트 버전 관리, 기능 플래그, 생성 로그, 폴백.

## 8. 감각이 부족한 사용자를 위한 보정 시스템
원칙: 사용자는 방향만, 조화는 시스템이 책임. 실패 원인: 취향 평균(글래스+브루탈 평균 = 어정쩡).
보정 4단계: 1) 가장 가까운 디자인 유형(검수된 프리셋)을 닻으로, 유형 내 허용 범위만 개인차 반영 2) 용도별 허용 범위로 클리핑 3) 조화 규칙으로 검증 조합에 스냅(원시값 직접 선택 없음) 4) 조화 점수 미달 시안 숨김.
조화 규칙: 2~3색·색채 이론 팔레트·WCAG AA, 검증 페어링·최대 2종, 모듈러 스케일 1.25·4/8pt, radius 한 계열, 장식 효과 최대 1~2, 상충 조합 목록.
용도별 예: 병원·금융·공공(신뢰, 강함) / 쇼핑몰(상품 그리드, 중간) / 레스토랑(사진, 중간) / SaaS(가치 전달, 중간) / 포트폴리오(약함). 가이드라인도 4장 파이프라인으로 갱신.
보조 강도: 선택 일관성 측정 → 일관되면 자유도↑, 엇갈리면 양자택일 추가 질문·프리셋 비중↑. 전문가 모드(접근성 규칙 유지).
보여주기: "추천 보정" 표현, 최종 3개 = 취향 그대로/용도 최적/균형, 충돌 시 이유 안내.
