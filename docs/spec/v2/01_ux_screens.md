# 01. 사용자 여정·화면 명세

이 장은 사용자가 보는 모든 화면(route), 화면 간 이동, 화면별 상태, 인터랙션 규칙, 서비스 UI 자체의 디자인 토큰, 접근성, 마이크로카피, 사용성 검증 계획을 정의한다. 진단 알고리즘(→ 02장), 토큰·택소노미 값(→ 03장), 생성 파이프라인·품질 게이트·컴파일러(→ 04장), 레퍼런스 데이터(→ 05장), API·인프라·세션(→ 06장), 출시 기준(→ 07장), 법무 문구·보관 기간(→ 08장)은 해당 장을 따른다. 용어·코드 식별자는 00장 §12 용어집과 통합 결정 `decisions_v2.md`(R-xx)를 그대로 쓴다(`survey_session`, `mockup`, `project`, `v_true`/`v_fit`/`v_bal`, `local_business`, 축 키 `expression`·`temperature`·`shape`·`density`·`depth`, 유형 `T1`~`T8` 등). 이 장은 화면 ID·route의 단일 원천이다(R-19). API 경로·오류 코드의 원천은 06장 6.4와 `@tastefit/api-contract`다(R-13·R-14).

표기: **[P0]** = MVP 필수, **[P2]** = Phase 2, **[P3]** = Phase 3, **MVP 제외** = MVP에서 구현하지 않음.

### 1.1.4 접근 권한과 로그인 지점 [P0]

| 행동 | 익명(`anon_id` 쿠키) | 로그인 필요 | 근거 |
|---|---|---|---|
| 진단 응답·이어하기·결과 보기 | O | — | D-41 |
| 공개 결과·공개 시안 열람, 신고 | O | — | 00장 §10.3 |
| 결과 공감 평가·앵커 유형 변경·결과 삭제 | O(소유자) | — | 소유 = 같은 `anon_id` 또는 귀속 계정 |
| 브리프 입력 | O(임시본) | 제출 시 | R-26, D-0103 |
| 시안 생성·비교·편집 | — | O | D-41 |
| 내보내기·시안 공유 링크 | — | O | D-41 |
| 내 기록(S12) | — | O | |

- 로그인 게이트는 **S06 "시안 만들기" 제출 시점 1곳**이다(`login_prompt_view{trigger='generate'}`). S12 직접 접근 시에만 `trigger='history'`. 진단·결과 단계에서는 로그인 유도 배너·모달을 노출하지 않는다.
- 첫 로그인(계정 생성) 직후 S05 동의 화면을 1회 거친다(08장 8.7.4 B). 동의가 없으면 프로젝트·생성 API는 `403 CONSENT_REQUIRED`(06장 6.4.2)를 반환하고 UI는 S05로 보낸다. 비공개 베타(`BETA_INVITE_ONLY=true`, R-32)에서 초대 코드가 없으면 `403 INVITE_REQUIRED` → S06에서 초대 코드 입력(1.12.2).
- 로그인 성공 시 같은 브라우저의 익명 진단 세션·결과·브리프 임시본을 계정에 귀속한다(D-41, 귀속 규칙 → 06장). 다른 브라우저에서 매직링크를 연 경우는 1.5.5.5의 `brief_draft_id`로 복구한다(`brief_drafts` TTL 24시간, R-26).
- 보관 기간 값(익명 30일 등)은 → 08장(D-0804). 이 장은 "만료" 상태 UI만 정의한다(1.12).

**AC-01-01** Given 익명 사용자, When 랜딩에서 진단을 시작해 결과까지 진행, Then 로그인 요청 UI와 `login_prompt_view` 이벤트가 0회다.
**AC-01-02** Given 익명 사용자가 브리프 필수 필드를 채움, When "시안 만들기" → 로그인 → 동의를 마치면, Then S06으로 돌아와 입력값 전체가 보존되고 생성 요청이 자동 제출된다(사용자 추가 클릭 0회).

## 1.3 공통 레이아웃·내비게이션 [P0]

### 1.3.1 브레이크포인트와 그리드

| 이름 | 폭 | 컬럼 | 거터 | 좌우 여백 | 콘텐츠 최대 폭 |
|---|---|---|---|---|---|
| mobile | 360~767px | 4 | 16px | 16px | 100% |
| tablet | 768~1023px | 8 | 24px | 24px | 100% |
| desktop | 1024~1439px | 12 | 24px | 32px | 1200px |
| wide | ≥ 1440px | 12 | 24px | auto | 1200px (S09만 100%) |

- 지원 폭 360~1920px, 360px에서 가로 스크롤 0. 기기 구분은 00장 §8.2 규칙(< 768 mobile, 768~1023 tablet, ≥ 1024 desktop)과 같다.
- 지원 브라우저(R-33): Chrome/Edge ≥ 111, Safari·iOS Safari ≥ 16.4, Firefox ≥ 128, Samsung Internet ≥ 22. 미지원 브라우저는 S01 상단에 "이 브라우저에서는 일부 기능이 동작하지 않을 수 있어요" 배너(차단하지 않음).
- S01~S08, S12, S13은 360px에서 끝까지 완료 가능해야 한다. S09 **편집 허용은 기기로 판정**한다: `matchMedia('(pointer: fine)').matches || screen.width >= 768`이면 편집을 허용하고, 터치 전용 소형 기기(휴대폰)만 1.8.7 읽기 전용 모드를 쓴다. **배치는 CSS 뷰포트로 정한다**: 편집 허용 상태에서 뷰포트 < 768이면 1열 편집 레이아웃(1.8.7)이다. 그래서 200% 확대로 뷰포트가 줄어도 편집이 사라지지 않는다(S-31, 00장 §7.1). **판정 시점(T-24)**: S09 마운트 시 1회 판정하고 그 세션(탭) 동안 고정한다(확대·회전·창 크기로 바뀌지 않는다). SSR은 판정 전까지 편집 스켈레톤을 그리고, 클라이언트 판정 뒤 편집 또는 읽기 전용으로 바꾼다. 이 판정이 "편집 허용 기기"·"편집 불허 기기"의 유일한 정의이며 내보내기 표시(1.9)·S08 주 CTA(1.7.1)·07장 7.6.2가 이것을 참조한다.

### 1.4.3 기기별 카드 비교 방식

크기 규칙의 원천은 이 표다(T-23, UX3-01. 옛 S-30 공식 일부 → T-23으로 대체). m = 좌우 여백(desktop 32, tablet 48), 간격 24.

```
w2 = min((vw − 2m − 24)/2, ((vh − 64 − 56 − 64 − 24)/2) × 1.6, 588)     // 2열 폭(desktop 1단계)
w2t = min((vw − 2m − 24)/2, 588)                                       // 2열 폭(tablet 1단계·desktop/tablet 2단계, 높이 제약 없음)
w1 = min(vw − 2m, 800)                                                 // 1열 폭
w_min = 480                                                            // 폭 하한(축소율 ≥ 0.375)
```

| 기기 | 1단계(4지) | 2단계(A/B) |
|---|---|---|
| desktop/wide | `(vw − 2m − 24)/2 ≥ 480`이면 2×2 그리드, 폭 `w2`(16:10). `w2 < 480`이 높이 항 때문이면 높이 제약을 풀고 2×2를 세로 스크롤로 보여 준다. 폭 항 자체가 480 미만(vw < 1072)이면 **1열 세로 목록**(폭 `w1`, 카드 4장을 `items` 순서대로 세로 배치, 페이지 스크롤). 클릭 = 선택. | `w2t ≥ 480`이면 좌우 나란히(폭 `w2t`). 아니면 mobile과 같은 **토글 비교**(desktop 자산, 폭 `w1`). 이미지는 `focus_region` 영역을 우선 노출(→ 02장 2.4.4). 클릭 = 선택. |
| tablet | `w2t ≥ 480`이면 2×2, 아니면 1열 세로 목록(폭 `w1`, 768px에서 672 = 축소율 0.525). 탭 = 확대 보기, 확대 화면의 "이걸로 할게요" = 선택. | desktop/wide와 같은 규칙(나란히 또는 토글), 탭 = 선택. |
| mobile | **전체 폭 페이저**: 카드 1장 폭 `vw − 32`(360px에서 328px), 고정 높이 창 `card_h = 100dvh − 276 − env(safe-area-inset-bottom)`(헤더 56 + 진행률 8 + 제목 48 + 하단 고정 바 120 + "다 별로예요" 44). 모바일 자산(780×1560, 1:2)을 `object-fit: cover; object-position: top`으로 표시하고 **카드 안 스크롤은 없다**. 전체를 보려면 "크게 보기"(세로 스크롤 라이트박스). 하단 고정 바(120)는 **두 줄**: 1줄 = 썸네일 4칸(각 64px) + "2 / 4", 2줄 = [이걸로 할게요](48px). "다 별로예요"는 하단 바 위 텍스트 버튼(44px). 썸네일 탭이 카드 이동의 단일 포인터 경로이고 좌우 스와이프는 보조다. | **토글 비교**: 같은 위치에 A 또는 B를 표시, 상단 세그먼트 [A][B]로 전환(스크롤 위치 유지). 1단계와 같은 고정 창 `card_h`, 하단 바 1줄 = 세그먼트, 2줄 = 응답 버튼. 처음 표시 = `items[0]`. 두 장 모두 1회 이상 본 뒤에만 "A로 할게요/B로 할게요/차이를 모르겠어요" 활성(비활성 시 안내 "B도 한 번 봐 주세요"). |

- **회전 안내**: `(pointer: coarse) && vh < 500`(가로로 돌린 휴대폰, 폭 판정 아님)이거나 mobile `card_h < 300`이면 "세로로 돌려 주세요" 안내를 띄우고 응답 버튼을 비활성으로 둔다. R5 자산 클래스(폭 ≥ 768 → desktop 자산)는 바꾸지 않는다.
- 1열 목록·토글 전환은 같은 문항 안에서 바뀌지 않는다(문항 표시 시 1회 판정, 창 크기 변경 시 다음 문항부터 반영). 응답에는 `ux.layoutMode ∈ {grid2x2, list1, pair, toggle, pager}`를 함께 기록한다.

- mobile 1단계는 일부만 보고 선택할 수 있다(강제 순회 없음). 실제로 본 카드를 `ux.viewedItemIds`로 기록.
- 응답마다 `ux.viewportClass` 옆에 `ux.cardScale`(실제 카드 폭 / 자산 폭, 소수 2자리)을 기록한다(S-30). mobile 자산이 없는 문항은 mobile 세션의 후보에서 빠진다(02장 2.6.1 (f)). 출시 데이터 검사에서 mobile 자산 누락은 0건이어야 한다.
- 이미지는 R-07의 2벌 자산만 쓴다(추가 해상도 생성 없음). 다음 문항 이미지는 응답 직후 선로딩(02장 2.4.5).

### 1.4.4 선택 인터랙션

1. 선택 즉시 선택 카드 3px `--svc-fg` 외곽선 + 체크, 나머지 불투명도 0.4(`prefers-reduced-motion`이면 전환 0ms).
2. 300ms 후 다음 문항. 300ms 안에 다른 카드를 누르면 선택이 바뀌고 300ms 재시작.
3. 응답은 전환과 동시에 서버 저장. 다음 문항 페이로드는 응답 API 반환값으로 받는다(→ 06장). 다음 이미지가 준비 전이면 R1 스켈레톤.
4. `latency_ms` = 이미지 동시 공개 시각 → 선택 시각(라이트박스·페이저 이동 포함).
5. `latency_ms < 1000`이 3문항 연속이면 토스트 "천천히 보셔도 돼요"를 세션당 1회. 가중치 처리 → 02장.

### 1.4.6 이전 문항(뒤로가기 1단계)

- 위치: 헤더 좌측 "← 이전 문항"(첫 문항 숨김).
- 직전 1문항으로만 돌아간다. 돌아간 문항에 다시 응답하기 전까지 추가 이전은 비활성(`aria-disabled="true"`, 툴팁 "한 문항만 돌아갈 수 있어요"). 재응답 후 다시 1회 가능.
- 돌아간 문항은 **같은 자극물·같은 순서**로 보이고, 이전 응답이 선택 표시로 미리 채워진다. 앱은 `POST /api/surveys/:id/undo {fromSeq}`(06장) 후 새 응답을 보낸다(이력은 서버 원본 로그 보존, 이벤트 `survey_back`). `409 UNDO_NOT_ALLOWED`면 토스트 "이전 문항으로는 한 번만 돌아갈 수 있어요". 2단계 이후 문항은 새 응답 기준으로 다시 선택(→ 02장).
- 2단계 첫 문항에서 이전 = 1단계 8번(전환 화면 건너뜀).

### 1.4.7 진행률

- 표시: 막대 + 텍스트. "1단계 · 3 / 8", "2단계 · 최대 8문항 중 2", 전환 화면 "1단계 완료".
- 막대 값: 1단계 `p = answered1/16`, 2단계 `p = (8 + answered2)/16`, 종료 `p = 1`(조기 종료 시 점프). 표시값 `p_shown = max(p_shown_prev, p)` — 이전 문항으로 가도 막대는 줄지 않는다(텍스트 카운터만 실제 위치).
- `role="progressbar"`, `aria-valuemin=0`, `aria-valuemax=16`, `aria-valuenow=응답 수`, `aria-valuetext="16문항 중 3문항 완료"`.
- S01과 1단계 첫 문항에 "약 4분 · 16문항 이내" 표시.

### 1.4.8 단계 전환 화면

- 1단계 8번 응답 직후 S02 안에서 표시. 제목 "큰 취향을 찾았어요. 이제 세부를 좁혀 볼게요", 잠정 키워드 2개(클라이언트가 현재 `SurveyView.state.mu`에서 |μ−0.5|가 큰 두 축을 골라 1.5.2.1 표의 해당 극 라벨을 표시, 예: "따뜻한 · 여유로운"), 버튼 "계속하기"(표시 800ms 후 활성, 자동 넘김 없음).

### 1.4.9 시작·이어하기·나가기

- 시작: S01 "진단 시작" → `POST /api/surveys {entry, restart?}`(06장, `anon_id` 쿠키 없으면 발급) → `/d/[sessionId]`. 시작 버튼 아래 08장 8.7.4 A 고지 1줄. S01의 선택 칩 "어떤 사이트를 생각하고 있나요? (선택)"(`saas`/`portfolio`/`local_business`/"아직 모르겠어요") 값은 `purpose_hint`로 저장해 사전분포(02장 2.8.1)와 S06 용도 기본값에 쓴다.
- 저장: 응답마다 `POST /api/surveys/:id/responses {seq, itemKey, shownItemIds, answer, chosenItemId?, latencyMs}`(06장). 다음 문항은 응답의 `SurveyView.question`으로 받는다. 오프라인이면 마지막 응답을 보관하고 오프라인 배너와 함께 대기, 복귀 시 같은 `seq`로 재전송(서버 멱등). `409 SEQ_CONFLICT`면 `GET /api/surveys/current`로 다시 맞춘다.
- 나가기: 확인 시트 "지금까지 응답은 저장돼요. 언제든 이어서 할 수 있어요" [나가기][계속하기] → S01.
- 재방문: S01 진입 시 `GET /api/surveys/current`로 만료 전 미완료 세션(30분 무활동 `abandoned` 포함, 02장 2.7)이 있으면 배너 "진단을 이어서 할까요? (16문항 중 n문항 완료)" [이어서 하기][처음부터]. "처음부터"는 `POST /api/surveys {restart:true}`(기존 세션 `abandoned`).
- 시즌 릴리스로 세션의 `taxonomy_version`이 무효(→ 05장)면 배너 대신 "진단 문항이 새로 바뀌어 처음부터 시작해요"를 표시하고 새 세션.

#### 1.5.2.1 5축 양극 막대

#### 1.5.5.2 `BrandInput` 스키마(단일 원천, R-21 — 06장 API·07장 TC-B·골든 세트가 참조)

API 필드는 camelCase(06장 6.4.1). 용도와 예시 사용 여부는 `BrandInput` 밖의 프로젝트 생성 요청 필드다.

```ts
type Purpose = 'saas' | 'portfolio' | 'local_business';   // R-02

type PrimaryAction =
  | 'signup' | 'demo' | 'download'          // saas
  | 'view_work' | 'resume'                  // portfolio
  | 'reserve' | 'visit' | 'menu'            // local_business
  | 'contact';                              // 공통

type BrandInput = {
  name: string;                     // 필수, 브랜드명 1~30자(grapheme)
  description: string;              // 필수, 한 줄 소개 10~80자
  primaryAction: PrimaryAction;     // 필수, 용도별 허용값(아래 표)
  primaryActionLabel?: string;      // 선택, 2~12자, 기본 = 표의 라벨
  audience?: string;                // 선택, ≤ 40자
  keyPoints?: string[];             // 선택, 0~3개, 각 2~40자, 정규화 후 중복 금지
  brandColor?: string;              // 선택, 1개(04장·R-21). 입력은 `#RGB` 또는 `#RRGGBB`(대소문자 무시) → `#RRGGBB` 대문자로 정규화(03장 3.13)
};

// 프로젝트 생성(06장): POST /api/projects
type ProjectCreate = {
  resultId: string;
  purpose: Purpose;                 // 필수
  brand: BrandInput;
  useSampleContent: boolean;        // "예시로 채우기" 후 수정 없이 제출하면 true
  brandAttested?: boolean;          // BRAND_ATTESTATION_REQUIRED 후 체크 시 true
};
// 이어서 POST /api/projects/:id/generations {kind:'initial'} + Idempotency-Key (R-14)
```

| `purpose` | 칩 라벨 | `primaryAction`(라벨) | `description` placeholder |
|---|---|---|---|
| `saas` | SaaS·앱 소개 | `signup`(무료로 시작하기), `demo`(데모 신청하기), `download`(앱 내려받기), `contact`(문의하기) | 예: 프리랜서의 세금 신고를 10분 만에 끝내 주는 앱 |
| `portfolio` | 포트폴리오·개인 브랜드 | `view_work`(작업 보기), `contact`(작업 의뢰하기), `resume`(이력 보기) | 예: 브랜드 사진을 찍는 서울의 포토그래퍼 |
| `local_business` | 카페·식당·공방 | `reserve`(예약하기), `visit`(오시는 길), `menu`(메뉴 보기), `contact`(문의하기) | 예: 망원동에서 매일 아침 굽는 사워도우 빵집 |

- 연락처·주소·영업시간·가격·대표자명·사업자번호 필드는 두지 않는다. 시안의 해당 슬롯은 항상 예시값 또는 `[예시]` 플레이스홀더(08장 8.6·8.7.5, → 04장).
- 로고·사진 업로드 = **MVP 제외**(R-21, 08장 D-0803). 07장 TC-B-09·10은 [P2](R-21).

## 1.6 생성 대기 (S07) [P0]

생성 파이프라인·폴백·SLO 판정 → 04장, 큐·상태 API → 06장. 생성 요청 `POST /api/projects/:id/generations`는 202 + `GenerationView`를 돌려주고, 클라이언트는 `GET /api/generations/:jobId`를 폴링한다(2초, 경과 60초 이후 5초, 서버가 준 `pollAfterMs` 우선, `If-None-Match` 사용; SSE는 [P2], R-14).

### 1.6.1 사용하는 상태 뷰(06장 6.4.3 `GenerationView` 그대로)

```ts
type JobStatus = 'queued' | 'running' | 'succeeded' | 'partial' | 'fallback' | 'failed' | 'canceled'; // R-15
type JobPhase  = 'queued' | 'compiling' | 'generating' | 'rendering' | 'scoring'
               | 'repairing' | 'fallback' | 'selecting' | 'done';                                  // 06장 6.2.3
// GenerationView = { jobId, status, phase, progressPct, queuePosition, queuedAt, startedAt, finishedAt,
//                    mockups: MockupCard[] /* 노출 확정분 0~3, 점진 추가 */, errorCode, pollAfterMs }
// MockupCard     = { mockupId, variant: 'v_true'|'v_fit'|'v_bal', isFallback, harmonyScore, tasteScore,
//                    previewUrl, screenshotUrl /* 1280 첫 화면 */, labelKey, brandColorNotice, useSampleContent }
```

- `MockupCard`에는 `brandColorNotice: null | 'adjusted' | 'demoted_to_accent' | 'used_as_tint' | 'ignored'`, `useSampleContent: boolean`, `movedAxes`, `diffFromTrue`도 있다(06장 6.4.3, S-32·S-37).
- `harmonyScore`·`tasteScore`는 화면에 표시하지 않는다(1.7.1).

### 1.6.2 단계 표시(`phase` → 라벨, 06장이 01장에 위임)

| `phase` | 스텝 | 표시 문구 | 보조 |
|---|---|---|---|
| `queued` | — | 순서를 기다리고 있어요 | "앞에 {queuePosition − 1}건"(동시 생성 전역 5건·사용자당 1건 제한, R-16). `queuePosition = 1`이면 "곧 시작해요" 대신 "다음 차례예요" |
| `compiling` | ① | 디자인 명세 만드는 중 | — |
| `generating` | ② | 시안 그리는 중 | — |
| `rendering`, `scoring` | ③ | 화면 크기별로 확인하는 중 | — |
| `repairing` | ③ | 기준에 못 미친 시안을 다시 그리는 중 | — |
| `fallback` | ③ | 기본 구성을 준비하는 중 | "자동 구성이 기준에 못 미친 방향은 기본 구성으로 채워요" |
| `selecting` | ④ | 세 가지 방향 고르는 중 | — |
| `done` | ✓ | 다 만들었어요 | S08로 전환 |

- 세로 4단 스텝(완료 ✓ + 텍스트, 진행 중 굵게, 대기 `--svc-fg-muted`) + 스텝 아래 얇은 막대(`progressPct`, 서버가 실제 진행 이벤트로 계산한 값만 사용). 타이머 기반 가짜 애니메이션 금지. 화면 변화는 폴링 응답 수신 시에만.
- 경과 시간 "0:42" = 현재 − `queuedAt`(대기 포함, 06장 SLO 측정 구간과 같음), 1초 단위 로컬 보간 허용.
- 진행 영역 `aria-live="polite"`: 스텝이 바뀔 때만 1회 낭독.

### 1.6.3 대기 중 콘텐츠

- desktop: 왼쪽 단계 표시, 오른쪽 시안 슬롯 3개(취향 그대로 → 용도 최적 → 균형 순서 고정). mobile: 단계 표시 → 슬롯 세로 3개.
- 미완성 슬롯 = 스켈레톤 + 변형 라벨. `mockups`에 들어온 변형은 즉시 `screenshotUrl` 썸네일로 교체(**첫 카드 노출 p50 ≤ 45초, 전체 p50 ≤ 60초·p95 ≤ 90초**, R-25). 폴백 카드는 "기본 구성" 배지.
- 하단: 내 유형 설명 2문장 + "이 시안에 적용 중인 규칙" 3줄 — 결과의 디자인 가이드(`ResultView.guide`: 서체 페어링명, radius 계열명, 팔레트 첫 색 이름)에서 클라이언트가 만든다(서버 추가 필드 없음).

### 1.6.4 시간 경과 규칙(R-25, 06장 6.2.4)

| 경과(`startedAt` 기준) | 화면 변화 |
|---|---|
| 대기 중(`queued`) | 대기 순번만 표시. 대기 60초 초과 시 "사용자가 많아 조금 기다리고 있어요. 이 화면을 닫아도 순서는 유지돼요" |
| 0~90초 | 기본 |
| 90초 | 보조 문구 "평소보다 조금 걸리고 있어요. 이 화면을 닫아도 계속 만들어요" |
| 120초 | 서버가 폴백 경로로 전환(`phase='fallback'`), 확정 카드가 있으면 [지금 나온 시안 먼저 보기] 노출 |
| 180초 | 서버 강제 종료(`GEN_TIMEOUT`). 노출 ≥ 1 → 상태(R-15)에 따라 S08 전환. 노출 0 → `failed` 화면(1.12), 한도 환불 |

## 1.7 시안 비교 (S08) [P0]

`status ∈ {succeeded, partial, fallback}`이면 같은 route에서 S08 레이아웃으로 전환(새로고침 없음). 상태 판정은 R-15(비폴백 노출 3 = `succeeded`, 1~2 = `partial`, 0이면서 폴백 ≥ 1 = `fallback`, 노출 0 = `failed`).

### 1.7.1 구성

| 영역 | desktop(≥1024) | tablet·mobile(<1024) |
|---|---|---|
| 큰 미리보기 | 왼쪽 8컬럼, 선택 변형의 `previewUrl` iframe(다른 등록 도메인, `sandbox=""`, R-17). 1280 또는 375 뷰포트를 영역 폭에 맞춰 `transform: scale` 축소, 내부 스크롤 | 전체 폭 페이저(변형 좌우 스와이프 + [이전][다음] 버튼), mobile 기본 375 |

| 뷰포트 토글 | 미리보기 상단 [데스크톱][모바일] | 같음 |
| 기타 | [전체 화면으로 보기](미리보기 도메인 새 탭), [같은 정보로 다시 만들기](확인 시트 "생성 횟수 1회가 사용돼요(오늘 남은 {d}회)" → `POST /api/projects/:id/generations {kind:'regenerate'}`), [다른 정보로 만들기](S06, 같은 결과) | 같음 |

- 변형 라벨(R-03)과 정의 1줄(고정 문구, `labelKey`로 카피 표에서 찾음):
  - `v_true` "취향 그대로" — "진단한 취향에 가장 가깝게 만들었어요"(S-32. 보정이 있었다면 이 카드에도 아래 보정 칩이 붙는다)
  - `v_fit` "용도 최적" — "{용도 라벨}에 맞게 구성과 대비를 조정했어요"
  - `v_bal` "균형" — "취향과 용도 사이에서 균형을 잡았어요"
  - `isFallback = true`: 변형 라벨은 그대로 두고 "기본 구성" 배지 + "이 방향은 자동 구성 대신 기본 구성으로 준비했어요"(04장 4.12)
- **보정 칩**(S-32): `MockupCard.movedAxes`(최대 2)를 문구 템플릿으로 보여 준다. `reason=purpose` → `calib.purpose` "{용도}에서는 {축}을 {방향}으로 조정했어요", `reason=type` → `calib.type` "{유형 이름}의 범위 안에서 {축}을 {방향}으로 맞췄어요", `reason=distance` → `calib.distance` "다른 시안과 구분되도록 {축}을 {방향}으로 옮겼어요". {축}·{방향}은 02장 축 쉬운 말(1.5.2.1 양 끝 라벨).
- **취향 그대로와 다른 점**(S-32): `v_fit`·`v_bal`에는 `MockupCard.diffFromTrue` 상위 2개를 L2 쉬운 말 사전(`l2.plain.<key>.<value>`, 1.15.3, 예: "더 촘촘한 여백 · 각진 모서리")으로 보여 준다. `v_true`는 표시하지 않는다. "원래대로 보기" 토글은 [P2](00장 §7.1).
- 그 아래 브랜드 컬러 안내(`brand_color_notice` 5값, 1.5.5.3), `useSampleContent`면 "예시 콘텐츠" 배지. 업종에 맞는 사진이 없어 일부를 색면으로 바꾼 시안은 `drafts.photoSubstituted`를 표시한다(S-34, 04장 4.9.4).
- 점수(`harmonyScore`·`tasteScore`) 숫자는 표시하지 않는다(노출 시안은 모두 기준 통과).
- 카드 순서 고정: `v_true`, `v_fit`, `v_bal`. 위치 편향은 `mockup_select.variant`로 사후 점검.
- 미리보기를 처음 볼 때 `mockup_view` 1회(변형별).

### 1.7.2 부분 성공·폴백

- `partial`: 비폴백 시안 + 누락 변형을 채운 "기본 구성" 카드로 3칸이 모두 찬다(04장 4.12). 안내 "일부 방향은 기본 구성으로 준비했어요". 한도 차감(R-15).
- `fallback`: 3칸 모두 "기본 구성" + 안내 "이번엔 기준에 맞는 자동 구성을 만들지 못해 기본 구성으로 준비했어요. 생성 횟수는 줄지 않았어요"(R-15 환불) + [다시 만들기](`kind:'regenerate'`).
- 파이프라인 내부 재생성 1회(D-23) 외에 무료 추가 생성 버튼은 두지 않는다.

### 1.8.5 미리보기·반영 성능·즉시 검증(R-17)

- **미리보기 갱신**: 조작마다 `EditState`를 갱신하고 `deriveTokens` + isomorphic 컴파일러(04장 4.9)로 브라우저에서 HTML 전체를 다시 만들어, 표시용 iframe(`sandbox=""`, 스크립트 0)의 `srcdoc`을 통째로 교체한다. postMessage 프로토콜은 쓰지 않는다. 표시 iframe은 내부 스크롤을 쓰지 않는다: 측정용 iframe에서 잰 문서 높이로 iframe `height`를 지정하고 스크롤은 부모의 미리보기 컨테이너가 담당한다(교체해도 스크롤 위치 유지). 깜빡임을 막기 위해 새 `srcdoc`을 숨김 iframe에 먼저 넣고 `load` 후 표시 iframe과 교대(더블 버퍼)한다. 구조 변경 시 바뀐 섹션 위치를 `slotRects`로 찾아 컨테이너를 그 위치로 스크롤하고 오버레이 하이라이트 1초.
- **슬롯 선택**: 같은 HTML을 화면 밖 측정용 iframe(`sandbox="allow-same-origin"`, 스크립트 불가)에 넣어 `data-slot-id` 요소의 `getBoundingClientRect()`로 `slotRects`(slot_id → 사각형 목록)를 계산한다(04장 D-0413). 부모 페이지가 미리보기 위에 투명 오버레이를 그리고, 호버 시 1px `--svc-fg` 점선 외곽선, 클릭 시 해당 슬롯 선택·패널 포커스. 오버레이 슬롯은 키보드로도 순회 가능(Tab, 접근 가능한 이름 = "{섹션 이름} {슬롯 이름} 편집").
- **반영 시간**: 스타일 조작 → 표시 p95 ≤ `perf.editStyleP95Ms`(200ms), 구조 변경(섹션·variant·텍스트·이미지) → p95 ≤ `perf.editStructP95Ms`(500ms)(R-17). 서체의 첫 로드는 측정에서 제외하고, 같은 서체 재사용 시에는 포함한다(S-40).
- **폰트**(S-40, 03장 3.7.5): 편집 미리보기와 후보 카드는 `ks-x-1001` 정적 서브셋 + `page` 보충 파일(서브셋 밖 글자만, 디바운스 1초)을 쓴다. 측정용 iframe은 `document.fonts.ready` 이후 `slotRects`를 계산한다.
- **즉시 검증**(조작마다, 순수 함수 `evaluateTokens(tokens, layout_tree)` ≤ 50ms, 04장 4.15.2):
  - 대비 AA 위반 → 03장 스냅 규칙으로 텍스트 색 토큰 자동 보정(`auto_fix` op) + 배너 "글자가 잘 읽히도록 글자색을 조정했어요". 보정 불가면 조작 거부 + "이 조합은 글자 대비가 부족해서 쓸 수 없어요"(07장 TC-D-04).
  - 조화 점수 < 80 → 적용 + 배너 "조화 점수가 기준보다 낮아졌어요 — {규칙 이름}" + [추천값으로 되돌리기]. 80 이상이 되면 자동 해제. 저장·내보내기 차단 사유는 아니다.
  - 직접 입력 카피의 AI 티 린터 error → 적용하되 텍스트 탭에 "이 문구는 저장할 수 없어요 — {사유}" 표시, 저장 시 거부.
- **서버 재검사**: 저장 시 서버가 같은 입력으로 다시 컴파일·대비 검사·편집 텍스트 남용 판정(G-13)(실패 422 `EDIT_GATE_FAILED`), 통과하면 버전 `gate_status='pending'` → 렌더 게이트(p95 ≤ `perf.versionGateP95Sec`) → `passed | failed`(1.8.6).

- [원본과 비교]: desktop 누르는 동안, tablet 토글로 미리보기를 v1로 표시.
- **저장**: ① 로컬 백업 — op마다 `localStorage.tf_edit_{mockupId}`에 즉시 기록 ② 서버 저장 — 마지막 op 후 5초 무입력, [저장] 버튼, 내보내기·공유 직전에 `POST /api/mockups/:id/versions {baseVersionId, editState, trigger: 'autosave'|'manual'|'pre_export'|'pre_share'}`(헤더 `Idempotency-Key`) → 새 버전(append-only). 직전 버전과 `render_hash`가 같으면 요청하지 않는다(06장). 저장 중 추가 op는 다음 저장으로 넘긴다.
- **저장 상태 표시**(헤더): "저장 중…" → "저장됨 · 확인 중"(`gate_status=pending`) → "저장됨"(`passed`) / "확인에서 문제 {n}건"(`failed`, 클릭 시 문제 목록). 실패 시 2·4·8초 재시도, 3회 실패 후 `CLIENT_SAVE_FAILED` 배너.
- **렌더 게이트 실패 목록**: `gate_report.hard[].code = GATE_FAILED:<id>`를 쉬운 말로 표시 — G-04 "화면 폭을 넘치는 요소가 있어요", G-05 "글자가 칸에서 잘려요", G-06 "요소가 겹쳐요", G-08 "접근성 검사에서 문제가 있어요", G-09 "AI 티 규칙에 걸린 표현이 있어요", G-10 "브랜드명이 메뉴·첫 화면·하단 중 빠진 곳이 있어요", G-11 "특정 사이트와 너무 비슷해요", 그 외 "확인에서 문제가 있어요". 각 항목에 뷰포트와 섹션 이름, [그 섹션으로 이동]. 제안 문구: G-04·G-05 → "문구를 줄이거나 '다른 문구'를 골라 보세요, 또는 글자 크기 대비를 한 단계 낮춰 보세요".

## 1.10 공유 (S11·S13)·신고 [P0]

### 1.10.1 S11 시안 공유 설정

- 토글 "링크가 있는 누구나 볼 수 있어요"(기본 꺼짐). 처음 켜면 현재 버전을 저장(1.8.6)한 뒤 `POST /api/share {targetType:'mockup', targetId:mockupId, versionId}` → `PATCH /api/share/:shareId {isPublic:true}` → 링크 + [복사]. 이벤트 `share_link_enable`, 첫 공개 시 `mockup_adopted{via:'share'}`.
- 공유 링크는 **공유한 시점의 버전**을 보여 준다(06장 `share_links.version_id`). 이후 편집하면 S11에 "공유 중인 화면은 {n}번째 저장본이에요" + [최신 저장본으로 새 링크 만들기](`DELETE` 후 새 `POST`, 이전 링크는 404) 안내.
- 끄면 `PATCH {isPublic:false}`(`share_link_disable`), 이후 접근 404(공개 페이지 캐시 반영 ≤ 60초, 06장 6.7). 다시 켜면 같은 링크가 다시 열린다.
- 대상 버전이 `gate_status ≠ passed`면 `409 VERSION_GATE_NOT_PASSED` → "확인이 끝난 저장본만 공유할 수 있어요"(1.8.6 상태 표시로 안내).
- `SHARE_PUBLIC_ENABLED=false`(00장 KS-3, `503 SHARE_DISABLED`)면 토글 비활성 + "지금은 공유 기능이 잠시 멈춰 있어요".

### 1.10.2 S13 공유 시안 보기 `/p/[shareId]`

- 데이터 `GET /api/share/:shareId`(`ShareView`). 상단 고정 배너(08장 8.9.4, 제거 불가, 높이 ≥ 40px): "취향핏에서 AI로 만든 시안 미리보기입니다. 실제 서비스가 아닙니다. [신고]".

- 페이지 `<title>` = "취향핏으로 만든 시안"(브랜드명은 미리보기 안에만). `noindex,nofollow`.

- 신고로 비공개된 링크는 `410 SHARE_HIDDEN` → S15 "신고로 검토 중인 페이지입니다".

### 1.10.3 신고 모달(S03 공개 보기·S13)

- 사유 라디오: 사칭 / 피싱 / 저작권 침해 / 상표 침해 / 불법·유해 / 기타(enum `impersonation|phishing|copyright|trademark|inappropriate|other`, 00장 §10.3·08장 8.9.5), 설명 ≤ 1,000자(선택), 회신 이메일(선택).

## 1.13 서비스 UI 디자인 방향과 `--svc-*` 토큰 [P0]

### 1.13.1 콘셉트: "조용한 작업대(Quiet Workbench)"

1. **크롬과 콘텐츠 분리**: 서비스 UI(크롬)는 무채색 + 강조색 1개만. 색과 개성은 사용자의 시안·자극물만 가진다. 시안·자극물 프레임은 1px 무채색 테두리만, 그 주변에 강조색·그림자·배경 패턴을 두지 않는다.
2. **에디토리얼 톤**: 디자인 잡지·스튜디오 도구 톤. 유형 이름·H1에는 세리프 디스플레이 서체, 그 밖의 UI는 고딕 1종.
3. **비대칭과 정렬**: 12컬럼 위의 비대칭 배치(예: 7+5), 왼쪽 정렬 기본. 정중앙 히어로 금지.
4. **자기 린터 통과**: 서비스 화면도 AI 티 린터(D-28, 규칙 → 04장)와 아래 서비스 추가 규칙(SVC-L)을 통과한다.
5. **shadcn/ui는 동작만**: Radix primitive의 접근성 동작만 쓰고, 기본 테마 변수(zinc/slate HSL, `--radius: 0.5rem`, 기본 폰트, Lucide 아이콘)는 모두 `--svc-*`로 덮어쓰거나 제거한다(D-28).

### 1.14.3 진단 카드 접근성

- 1단계: 카드 4장 = `role="radiogroup"`(`aria-labelledby`=문항 제목), 각 카드 `role="radio"`, `aria-checked`. Tab으로 그룹 진입, ←/→/↑/↓ 이동, Enter/Space 선택. 2단계 A/B도 같은 구조.

- 단축키 1~4, A/B는 문항 영역에 포커스가 있을 때만 동작하고 설정에서 끌 수 있다(2.1.4).
- 문항 전환 시 포커스를 새 문항 제목(`tabindex="-1"`)으로 옮기고 진행률 `aria-valuetext`가 낭독된다.
- mobile 페이저: 카드 이동의 단일 포인터 경로는 하단 바 1줄의 **썸네일 탭**이다(옛 [이전 카드][다음 카드] 버튼 → T-23으로 대체). 스와이프는 보조라 2.5.1 경로 기반 제스처 대체를 충족한다. 썸네일은 `role="tab"`, 현재 카드 `aria-selected`.

## 1.17 사용성 테스트 계획 [P0]

라운드·인원·측정·통과 기준은 00장 §5.3이 단일 출처이고 출시 게이트 연결·이슈 처리는 07장 7.9다(5명 × 2라운드, 과제 성공률 ≥ 80%, SUS ≥ 70, T1 중앙값 ≤ 4분, Blocker 이슈 0). 이 절은 과제 스크립트(T1~T4는 00장 과제와 같고, T5는 R2 추가 과제)와 UX 관찰 항목을 정한다. 진단 타당성(블라인드 선호·재검사 일치)은 → 00장 §5.1·07장.

### 1.17.1 과제 스크립트

| 과제 | 시작 화면 | 진행자 지시(그대로 읽음) | 성공 정의 | 실패 정의 |
|---|---|---|---|---|
| T1 진단 | S01 | "이 서비스로 내 디자인 취향을 알아봐 주세요." | 힌트 없이 S03 도달 | 힌트 사용, 10분 초과, 중도 포기 |
